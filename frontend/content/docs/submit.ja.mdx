---
title: プラグインの登録
description: npm パッケージや GitHub リポジトリをレジストリに登録して、dsh.fish にプラグインを公開します。レジストリが実際の manifest を読み直すので、カタログの項目を手で書くことはできません。
---

dsh.fish にプラグインを載せるには、説明文ではなくソースを登録します。[登録フォーム](/submit)は npm パッケージか GitHub リポジトリをレジストリに指示し、レジストリはクローラーと同じリーダーで実際の manifest を読みます。カタログに載る内容は harness が実際に読み込む内容と同じで、手で書き換えられる項目はありません。

## 先にサインイン

登録にはサインイン済みのブラウザセッションが必要です。harness が持つデバイストークンは検索、インストール、評価には使えますが、あなたの代わりに公開することはできません。サインアウトした状態で `/submit` を開くと、サインインを求められ、そのあとフォームに戻ります。

## フォームの入力

フォームで入力するのはタイプ、ソース、任意のレビュー用メモです。

タイプはソースの種類だと思うもので、バンドル、プロファイル、スキル、エージェントプリセットのいずれかです。ソースは `npm:<package>` または `github:<owner>/<repo>[/<path>]` と書きます。メモが読まれるのは、登録が人のレビューに回ったときだけです。

## レジストリのチェック

選んだタイプは、どの manifest を先に調べるかをリーダーに伝えるだけです。スキルなら `SKILL.md` を最初に調べます。これは証拠ではありません。見つかった種類が選んだものと違えば登録は拒否されます。harness の manifest がまったく見つからない場合も同様で、たとえばバンドルは package.json に `dsh.bundle` を宣言する必要があります。

## 即時承認か、レビュー待ちか

ソースが読めて、あなたの所有だと証明できる登録は、その場で承認されます。

所有とは、リポジトリのオーナー id がサインインした GitHub アカウントと一致することです。両者は GitHub の数値 id で比較されるので、ユーザー名を変えても偽れません。

npm パッケージには同じ仕組みがなく、組織のリポジトリは個人ではなく組織の所有なので、この二つはレビュー待ちになります。

承認された登録には、公開されたアーティファクトへのリンクがその場で表示されます。レビュー待ちのものはメンテナーのレビュー後に表示されます。アーティファクトがすでに別のアカウントに取得されている場合は、衝突として拒否されます。

## 公開されたあと

アーティファクトの作成時や README の変更時には、ロケールごとに翻訳がキューに入ります。翻訳が提供されるのは現在の README と一致している間だけで、処理中、失敗、古くなった翻訳のときは原文が表示されます。
