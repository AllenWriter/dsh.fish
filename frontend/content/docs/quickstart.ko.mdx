이 튜토리얼은 빈 터미널에서 DeepSeek Harness 세션까지 네 단계로 안내합니다. DeepSeek Harness(`dsh`)는 [에이전트 하니스](/docs/concepts)입니다. 언어 모델이 도구를 들고 루프를 돌며 파일 읽기, 명령 실행, 코드 수정을 대신합니다. [세션](/docs/concepts)은 이 에이전트와 나누는 한 번의 대화입니다. 새 용어는 처음 나오는 자리에서 핵심 개념 페이지로 연결합니다.

API 키는 로컬에 저장되며 모델 요청은 dsh.fish를 거치지 않습니다.

## 1. Web UI 실행

```sh
npx @deepseek-ai/dsh web
```

이 명령은 `http://127.0.0.1:3080`에서 Web UI를 시작하고 브라우저를 엽니다. 브라우저가 열리지 않으면 그 주소로 직접 접속하세요. 패키지는 개발자 프리뷰입니다. 중요한 작업에 쓰기 전에 npm 안내와 릴리스 노트를 읽으세요.

## 2. 모델 연결

하니스에는 [모델](/docs/concepts)이 필요합니다. 모델은 사고를 담당하는 LLM으로, DeepSeek, Anthropic, OpenAI 같은 공급자가 제공합니다. **Settings → Models**를 열고 공급자의 API 키를 입력한 뒤 저장합니다. DeepSeek 카드는 키만 있으면 됩니다. 다른 공급자는 **Add provider**에서, 회사 게이트웨이나 자체 서버는 **Add a custom provider**에서 추가합니다. 키는 내 컴퓨터의 하니스 홈 디렉터리(`$DSH_HOME`)에 저장되고 dsh.fish로 전송되지 않습니다. 다음 요청부터 새 설정이 적용되며 다시 시작할 필요가 없습니다.

OpenAI 호환 엔드포인트는 base URL과 모델 식별자를 한 글자씩 확인하세요. 키 저장에 성공했어도 엔드포인트가 그 모델을 받아들인다는 뜻은 아닙니다. 긴 세션 전에 아래의 작은 첫 작업을 먼저 실행하세요.

## 3. 워크스페이스 선택

[워크스페이스](/docs/concepts)는 에이전트가 보고 바꿀 수 있는 프로젝트 디렉터리입니다. **Choose workspace**를 선택하고 검사할 저장소를 여세요. 워크스페이스를 선택하기 전에는 composer(아래쪽 메시지 입력란)를 쓸 수 없습니다.

워크스페이스를 신뢰 경계로 다루세요. 에이전트는 그 안에서 읽고 씁니다. 먼저 저장소 내용을 훑어보고 관련 없는 비밀이 든 디렉터리는 열지 마세요.

## 4. 첫 작업 실행

먼저 읽기 전용 요청을 전송합니다.

```text
Summarize this repository and identify its main packages.
```

응답에 언급된 파일이 실제로 있는지 확인하세요. 그다음 테스트 하나를 실행하는 것처럼 검증 가능한 작은 동작을 요청하세요. 요청된 권한과 최종 diff를 각각 검토합니다.

## 권한 이해하기

[권한](/docs/concepts)은 에이전트가 묻지 않고 실행할 수 있는 동작을 정합니다. 새 세션은 `workspace-write`로 시작합니다. 에이전트는 워크스페이스 안에 쓸 수 있지만 모든 읽기, 프로세스, 네트워크 동작이 격리되는 것은 아닙니다. 이해한 동작만 승인하고, 자격 증명은 워크스페이스 밖에 두고, 커밋 전에 변경을 검토하세요.
