要在 dsh.fish 上架插件，你提交的是源码，不是描述。[提交表单](/submit)把注册表指向一个 npm 包或 GitHub 仓库，注册表用爬虫同款的读取器去读真实的 manifest。写进目录的内容就是 harness 实际会加载的内容，任何目录字段都不能手写。

## 先登录

提交需要已登录的浏览器会话。harness 持有的设备令牌可以搜索、安装和评分，但不能替你发布。未登录时打开 `/submit`，页面会先请你登录，再带你回到表单。

## 填写表单

表单要填类型、来源和一条可选的审核备注。类型是你认为的来源种类：Bundle、配置档、技能、MCP 服务器、Agent 预设或 Hook 桥接。来源写作 `npm:<package>` 或 `github:<owner>/<repo>[/<path>]`。备注只有提交进入人工审核时才会被读到。

## 注册表检查什么

你选的类型只告诉读取器先查哪个 manifest：技能会先查 `SKILL.md`。它不是证据。注册表读到的种类和你选的不一致，提交会被拒绝；完全读不到 harness manifest 也会被拒绝，比如 Bundle 必须在 package.json 里声明 `dsh.bundle`。

## 立即通过或排队审核

来源可读、且能证明归你所有的提交会立即通过。所有权的含义是：仓库所有者的 id 和你登录的 GitHub 账户一致，两边按 GitHub 的数字 id 比较，改了用户名也冒认不了。npm 包没有对应的身份检查；组织的仓库归组织而不是归你。这两类都进审核队列。

通过的提交会直接给出已发布构件的链接。排队的提交在维护者审核后出现。构件已被其他账户认领时，提交会按冲突拒绝。

## 上架之后

构件创建或 README 变化后，站点按语言排队生成翻译。翻译只在仍与当前 README 匹配时提供；待处理、失败或过期的翻译一律显示原文。
