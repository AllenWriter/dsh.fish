dsh.fish에 플러그인을 올리려면 설명이 아니라 소스를 제출합니다. [제출 폼](/submit)은 npm 패키지나 GitHub 저장소를 레지스트리에 가리키고, 레지스트리는 크롤러와 같은 리더로 실제 manifest를 읽습니다. 카탈로그에 올라가는 내용은 harness가 실제로 불러오는 내용과 같으며, 어떤 필드도 손으로 쓸 수 없습니다.

## 먼저 로그인

제출에는 로그인된 브라우저 세션이 필요합니다. harness가 가진 기기 토큰은 검색, 설치, 평가에는 쓸 수 있지만 당신을 대신해 게시할 수는 없습니다. 로그아웃 상태에서 `/submit`을 열면 로그인을 요청한 뒤 폼으로 돌려보냅니다.

## 폼 작성

폼에는 유형, 소스, 선택적인 검토 메모를 적습니다.

유형은 소스가 어떤 종류라고 생각하는지로, 번들, 프로필, 스킬, MCP 서버, 에이전트 프리셋, 훅 브리지 중 하나입니다. 소스는 `npm:<package>` 또는 `github:<owner>/<repo>[/<path>]` 형식입니다. 메모는 제출이 사람 검토로 넘어갈 때만 읽힙니다.

## 레지스트리가 확인하는 것

고른 유형은 리더에게 어떤 manifest를 먼저 볼지만 알려 줍니다. 스킬이면 `SKILL.md`를 가장 먼저 봅니다. 이것은 증거가 아닙니다. 찾아낸 종류가 고른 것과 다르면 제출은 거부됩니다. harness manifest를 아예 찾지 못해도 거부되며, 예를 들어 번들은 package.json에 `dsh.bundle`을 선언해야 합니다.

## 즉시 승인 또는 검토 대기

소스를 읽을 수 있고 당신의 소유임이 증명되는 제출은 바로 승인됩니다.

소유란 저장소 소유자 id가 로그인한 GitHub 계정과 일치한다는 뜻입니다. 둘은 GitHub의 숫자 id로 비교되므로 사용자 이름을 바꿔도 속일 수 없습니다.

npm 패키지에는 이런 확인이 없고, 조직의 저장소는 개인이 아니라 조직의 소유이므로 이 둘은 검토 대기열로 갑니다.

승인된 제출에는 게시된 아티팩트로 가는 링크가 바로 표시됩니다. 대기 중인 제출은 관리자가 검토한 후에 나타납니다. 아티팩트를 이미 다른 계정이 소유하고 있다면 충돌로 거부됩니다.

## 게시된 후

아티팩트가 생성되거나 README가 바뀌면 로케일별로 번역이 대기열에 들어갑니다. 번역은 현재 README와 일치하는 동안에만 제공되며, 처리 중이거나 실패했거나 오래된 번역일 때는 원문이 표시됩니다.
