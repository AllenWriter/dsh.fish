아래 각 항목은 실제로 사용하는 페이지로 끝납니다.

## 에이전트 하니스

에이전트 하니스는 AI 모델을 에이전트로 바꾸는 프로그램입니다. 모델에 도구를 제공하고, 결과를 다음 단계를 위해 모델로 돌려보내고, 에이전트가 할 수 있는 일을 제한합니다.

DeepSeek Harness는 DeepSeek AI의 오픈 소스 하니스로, 모든 기능이 플러그인이 되도록 설계되었습니다.

사용 위치: [빠른 시작](/docs/quickstart).

## `$DSH_HOME`

Harness는 모든 사용자 데이터(프로필, 설정, 자격 증명, 세션 로그)를 하나의 루트 디렉터리에 보관합니다. `$DSH_HOME` 환경 변수가 설정되어 있으면 그것을, 아니면 `~/.dsh`를 사용합니다.

dsh.fish 설치 계획은 이 루트 또는 그 안의 프로필 디렉터리에만 씁니다.

사용 위치: [Hub 플러그인](/docs/hub)과 [CLI](/docs/cli) 설치.

## 프로필(profile)

프로필은 `$DSH_HOME/profiles/<name>` 아래의 디렉터리로, 하나의 Harness 설정을 정의하는 플러그인 패키지와 패치 파일을 담고 있습니다. 시작할 때 `--profile <name>`으로 선택하며, `web`과 `headless` 프로필은 처음 사용할 때 자동으로 생성됩니다.

dsh.fish는 모든 플러그인을 지정된 프로필에 설치합니다.

사용 위치: [CLI 설치](/docs/cli). 게시 방법은 [profile 형식](/docs/publish/profile)을 참고하세요.

## 세션(session)

세션은 여러분과 에이전트 사이의 한 번의 대화입니다. Harness는 세션을 추가 전용 이벤트 로그(메시지, 도구 호출, 승인)로 저장하고, 모델이 보는 내용은 그 로그에서 도출되므로 세션을 다시 재생하고 이어갈 수 있습니다.

세션은 워크스페이스별로 그룹화됩니다.

사용 위치: 세션 안에서 동작하는 [Hub 플러그인](/docs/hub).

## 워크스페이스(workspace)

워크스페이스는 Harness에 명시적으로 맡기는 프로젝트 디렉터리입니다. 선택하기 전까지 Web UI 입력창은 잠겨 있고, 선택 후에는 모든 세션이 해당 디렉터리를 작업 디렉터리로 실행됩니다.

워크스페이스를 신뢰 경계로 다루세요. 기본 권한에서 에이전트는 그 아래 어디든 쓸 수 있으므로 검토한 디렉터리를 선택합니다.

사용 위치: [빠른 시작](/docs/quickstart) 3단계.

## 모델과 제공업체

모델은 에이전트가 생각에 사용하는 AI이고, 제공업체는 모델을 제공하는 서비스입니다. DeepSeek 또는 직접 추가한 다른 제공업체를 쓸 수 있습니다. **Settings → Models**에서 제공업체의 API 키를 한 번 입력합니다.

키는 로컬의 `$DSH_HOME/.credentials.yaml`에 저장되며 dsh.fish로 전송되지 않습니다.

사용 위치: [빠른 시작](/docs/quickstart) 2단계.

## 권한(permissions)

권한은 에이전트가 도구로 무엇을 할 수 있는지 결정합니다.

권한은 이름 있는 프리셋으로 제공되며, 기본값인 `workspace-write`는 쓰기를 워크스페이스(와 임시 영역)로 제한하고 승인이 필요한 작업 전에 묻습니다. `danger-full-access`는 샌드박스를 제거하고 묻지도 않습니다.

사용 위치: [빠른 시작](/docs/quickstart)의 권한 안내.

## 플러그인(plugin)

플러그인은 Harness의 유일한 확장 메커니즘입니다. 코어는 의도적으로 작게 유지되고, 도구, 모델 제공업체, 승인 규칙은 모두 플러그인으로 불러와 프로필에 나열됩니다.

설치한 플러그인은 여러분이 Harness에 부여한 권한으로 동작합니다. 그래서 dsh.fish는 설치하기 전에 플러그인이 무엇이고 무엇을 하는지 검토할 수 있게 합니다.

사용 위치: [플러그인](/docs/plugins)과 [첫 플러그인](/docs/develop/first-plugin).
