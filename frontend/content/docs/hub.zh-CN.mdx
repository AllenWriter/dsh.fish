Hub 插件（`@dsh-fish/hub`）把 dsh.fish 目录带进正在运行的会话。智能体可以搜索构件、告诉你安装会执行什么，并在你同意后完成安装。你不需要离开会话。

## 添加插件

```sh
dsh plugin --profile <profile> add @dsh-fish/hub
```

`<profile>` 就是 harness 启动的那个配置档：原版 launcher 是 `web`，桌面端则是它自己启动的那一个。发布到 npm 的包已经带好构建产物 `lib/`，因此这条安装不会运行构建脚本，也不需要 `allowBuilds`。

### Local DSH

[Local DSH](https://github.com/stvlynn/local-dsh) 启动的是 `local-dsh`，而它的 launcher 在应用自带的 runtime 里，不在你的全局 `PATH` 上。用那个 launcher，插件才会装进应用真正启动的配置档：

```sh
APP_DATA="$HOME/Library/Application Support/com.localdsh.app"
RUNTIME="$(find "$APP_DATA/runtime" -maxdepth 1 -type d ! -name runtime ! -name '.partial-*' | head -n 1)"
export PATH="$RUNTIME/bin:$PATH"

dsh plugin --profile local-dsh add @dsh-fish/hub
```

然后重启 DSH——插件的工具在启动时加载。应用每次启动都会重写它自己管理的 bundle 列表，但会保留你添加的 bundle，所以插件在重启后仍然在。

### 从 git 安装

从 git 安装只是开发时的兜底方式，而且必须写上子目录：仓库根是一个 private workspace，不是这个插件。

```sh
dsh plugin --profile <profile> add github:stvlynn/dsh.fish#path:packages/dsh-plugin-hub
```

这份检出没有 `lib/`，所以会在安装时构建，而 pnpm 10 及以上版本在你明确允许之前会拒绝运行构建脚本。把 pnpm 打印出的包名复制到配置档案的 `pnpm-workspace.yaml` 里，再重新执行 `add`。这项允许意味着该包的代码会在安装时运行在你的机器上，处于智能体沙箱之外——请固定 commit，避免之后的推送改变要运行的内容。

### 从 `dsh-hub` 迁移

早前的版本是以 `dsh-hub` 这个名字从仓库根安装的：

```sh
dsh plugin --profile <profile> remove dsh-hub
dsh plugin --profile <profile> add @dsh-fish/hub
```

已经记录在 `$DSH_HOME/.dsh-fish-lock.json` 里的安装不受改名影响。

## 安装

`hub_install` 在这台机器上执行安装计划：

- 写入 skill 和 preset 文件
- 把 MCP 和 hook 行加入配置档案的补丁层
- 为 bundle 运行包管理器

完成后重启 harness，新配置才会加载。

如果计划中有从源码构建的包，`hub_install` 会拒绝执行，直到调用方传入 `allowBuildScripts: true`。这一步会在安装时把该包的代码运行在你的机器上，处于智能体沙箱之外，所以智能体必须回来问你，不能自行授权。

安装成功后记录在 `$DSH_HOME/.dsh-fish-lock.json`：

- `hub_list` 列出这台机器已安装的构件
- `hub_update` 为已安装的构件重新执行当前计划
- `hub_remove` 撤销一次已记录的安装（文件、补丁行、包）

这个锁文件与 `@dsh-fish/cli` 共用，所以 [CLI](/docs/cli) 看到的是同一份安装记录。

## 登录

登录后安装会记到你的账号下，并解锁 `hub_rate`。读取目录不需要账号。

`hub_account` 使用 `action: "login"` 发起一次 OAuth 设备流程登录：

- 工具返回一个短码和一个 URL
- 你在浏览器里打开 URL 并批准
- 插件会一直等待到你完成

智能体无法替你批准。

令牌写入 `$DSH_HOME/.dsh-fish-token.json`，文件权限为 0600，不会写入日志。

这个令牌刻意弱于浏览器会话。它能以你的身份读取目录、解析安装计划、给构件评分，但不能提交或认领构件。

## 设置页里的插件站

在带浏览器客户端的 harness 里，这个插件还会在设置页加一个 **dsh.fish** 分区，包含三个标签页。

- **浏览**：搜索目录，并在执行任何操作之前先展示某个构件的安装计划。会从源码构建的包，必须由你按下明确写着这一点的按钮才会继续。
- **已安装**：列出这个配置档通过 hub 安装的内容，也可以从这里移除。
- **账号**：用同一套设备流登录，把设备码和验证 URL 以普通链接的形式展示出来。

它是同一个安装器的第二个界面，而不是第二个安装器：这个分区调用的同源接口跑的就是 `hub_*` 工具跑的那段代码，写的也是同一份 `$DSH_HOME/.dsh-fish-lock.json`。所以「已安装」列出的内容与 `hub_list` 报告的完全一致。

任何与你账号有关的东西都不会进入浏览器。设备码和已保存的令牌都留在 host 一侧，这也正是桌面应用能把验证链接交给系统浏览器、而不是在应用窗口里打开的原因。

不提供浏览器客户端的配置档，仍然会加载这些工具。

## 安全

写文件的步骤被限制在解析后的 `$DSH_HOME` 内，试图越界的计划会被拒绝。

从源码构建的步骤需要你的明确同意，如上所述。

`hub_rate` 自带一条规则：智能体只给这台机器实际安装并使用过的构件评分，依据第一手证据，并在评分时告知你。

## 工具

| 工具          | 作用                                                   |
| ------------- | ------------------------------------------------------ |
| `hub_search`  | 按文本和构件类型搜索注册表。                           |
| `hub_show`    | 展示一个构件的详情，包括安装会执行的内容。             |
| `hub_install` | 在这台机器上执行安装计划。                             |
| `hub_list`    | 列出这台机器通过 hub 安装的构件。                      |
| `hub_remove`  | 撤销一次已记录的安装（文件、补丁行、包）。             |
| `hub_update`  | 为已安装的构件重新执行当前计划。                       |
| `hub_account` | 通过 OAuth 设备流程登录、查看状态或退出。              |
| `hub_reviews` | 社区评分：站内 1–5 星制、平均分、分布和评论。          |
| `hub_rate`    | 给已安装的构件打 1–5 星，可附公开评论。                |

## 配置

```yaml
- id: hub
  name: '@dsh-fish/hub'
  config:
    baseUrl: https://dsh.fish # 自托管部署只需要改这一项
    targetProfile: current # 或者具体的配置档案名
```
