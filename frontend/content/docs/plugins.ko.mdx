DeepSeek Harness는 플러그인 프레임워크인 Cordis 위에서 동작합니다. 모델 어댑터, 도구 레지스트리, 세션 로그, 에이전트 루프는 모두 설정에서 마운트되는 플러그인입니다. 고쳐야 할 특권 코어는 없습니다. Harness를 확장하려면 다른 플러그인 옆에 플러그인을 마운트하면 됩니다. 플러그인이 등록한 것은 언로드될 때 해제됩니다.

코어가 작게 유지되는 이유입니다. 새 기능이 필요하면 Harness 업그레이드를 기다리지 말고 플러그인을 추가하세요.

## 플러그인이 될 수 있는 것

dsh.fish 카탈로그는 여섯 가지 아티팩트 종류를 다룹니다. 각각 고유한 매니페스트 계약이 있습니다.

- [Bundle](/docs/publish/bundle): 프로필에 플러그인 patch 레이어를 추가하는 npm 패키지.
- [Skill](/docs/publish/skill): 에이전트가 필요할 때 불러오는 Markdown 지시 파일.
- [MCP server](/docs/publish/mcp-server): 네이티브 도구로 마운트되는 외부 Model Context Protocol 서버.
- [Agent preset](/docs/publish/agent-preset): 세션에 고유한 도구와 프롬프트를 부여하는 하나의 `agent.cordis.yml`.
- [Profile](/docs/publish/profile): 완전한 구성을 이루는 순서 있는 bundle 스택.
- [Hook bridge](/docs/publish/hook-bridge): 기존 Claude Code 또는 Codex 셸 훅을 dsh 안에서 실행.

## 신뢰 문제

플러그인은 당신이 Harness에 부여한 권한으로 실행되는 코드입니다. 워크스페이스 안에서 동작하고, git 설치는 에이전트 샌드박스 밖에서 패키지의 빌드 스크립트를 실행할 수 있습니다. README가 말하는 것은 작성자의 주장이지, 설치가 실제로 하는 일이 아닙니다.

dsh.fish는 바로 그 간극을 위해 존재합니다. 카탈로그는 각 소스의 실제 매니페스트와 파일을 읽고, 모든 아티팩트 페이지는 무엇이든 실행하기 전에 설치 계획(설치가 수행할 파일 쓰기, 패키지 추가, patch 행)을 보여줍니다. 먼저 검사하고, 그다음 설치하세요.

직접 플러그인을 만들려면 [첫 플러그인 만들기](/docs/develop/first-plugin)부터 시작하세요.
