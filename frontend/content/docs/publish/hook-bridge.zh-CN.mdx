---
title: Hook Bridge
description: 在 DeepSeek Harness 中运行你为 Claude Code 或 Codex 写好的 shell hooks。
---

Hook bridge 把你为 Claude Code 或 Codex 写好的 shell hooks 搬进 DeepSeek Harness 运行。和 MCP server 一样，Harness 没有为这种构件定义清单约定（它安装为 profile patch 中的一行 bridge 插件配置），所以 `package.json` 里的 `dsh.hub` 声明是事实来源。

## 清单约定

```json
{
  "dsh": {
    "hub": {
      "kind": "hook-bridge",
      "hook": {
        "dialect": "claude-code",
        "settingsPath": "hooks/settings.json"
      }
    }
  }
}
```

- `dialect` 为 `claude-code` 或 `codex`，表示 settings 文件使用哪种工具的 hook 格式。
- `settingsPath` 指向该文件，相对于仓库。绝对路径或越出仓库的路径会被拒绝。

声明残缺（只有 kind 没有对应块、dialect 非法、路径越出仓库）是 domain error。indexer 会跳过该仓库并记录错误；如果是你自己提交的仓库，错误会返回给你。

## settings 文件

`settingsPath` 指向一个普通的 Claude Code settings 文件（`hooks.json`，或任何带 `hooks` 键的 settings 文件）：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "bash",
        "hooks": [
          { "type": "command", "command": "./scripts/check-command.sh" }
        ]
      }
    ]
  }
}
```

matcher 匹配的是工具名，只有 `type: "command"` 的 hook 会运行。Claude Code 方言支持七个事件：`SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Stop`、`SubagentStart`、`SubagentStop`。Codex 方言使用相同的事件映射结构，支持其中五个（`SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Stop`），且只运行同步的 command hook。

## 安装机制

安装计划会在该 profile 的 `cordis.patch.yml` 层追加一行 bridge 插件，即 `@deepseek-ai/dsh-hooks-claude-code` 或 `@deepseek-ai/dsh-hooks-codex`：

```sh
npx @dsh-fish/cli add <artifact-id> --profile <profile>
```

Hook bridge 会以智能体的权限运行 settings 文件里的 shell 命令。安装前请先读一遍这个文件。
