MCP（Model Context Protocol）server 是一個外部程式或服務，Harness 把它的工具掛載為自己的原生工具。安裝後，模型可以像呼叫內建工具一樣呼叫它們，工具名形如 `mcp__github__create_issue`。

Harness 沒有為這種構件定義清單慣例：MCP server 安裝為 profile patch 中的一列外掛設定，而不是 Harness 直接載入的套件。`package.json` 裡的 `dsh.hub` 宣告是唯一的資料來源，目錄讀取的就是它。

## 清單慣例

```json
{
  "dsh": {
    "hub": {
      "kind": "mcp-server",
      "mcp": {
        "serverName": "github",
        "transport": "stdio",
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-github"],
        "credentials": [{ "envName": "GITHUB_TOKEN", "required": true }]
      }
    }
  }
}
```

- `serverName` 決定伺服器工具的命名空間：`mcp__<serverName>__<tool>`。它必須符合 `[A-Za-z0-9_-]{1,32}`。
- `transport` 為 `stdio` 或 `streamable-http`。stdio server 需要 `command`（`args` 選用）；HTTP server 需要 `url`。
- `credentials` 以 POSIX 環境變數名稱列出伺服器需要的密鑰。`required` 預設為 `false`。

單獨的 `dsh.hub.mcp` 區塊本身就宣告了類型。反過來（只有 `kind: "mcp-server"` 卻沒有 `mcp` 區塊）屬於宣告殘缺，會被拒絕而不是略過。

## 安裝機制

安裝計畫會在該 profile 自己的 `cordis.patch.yml` 層附加一列 `@deepseek-ai/dsh-mcp-client`（列 id 為 `mcp-<serverName>`），之後升級 Harness 不會覆寫它：

```sh
npx @dsh-fish/cli add <artifact-id> --profile <profile>
```

目錄只存憑據參照，不存密鑰值。產生的設定列中，每個密鑰在載入時從處理程序環境解析（`!!js process.env.GITHUB_TOKEN`），而每個必要憑據的值都要在伺服器執行前填入。這就是目錄列可以公開提供的原因。
