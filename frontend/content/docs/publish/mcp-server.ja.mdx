MCP（Model Context Protocol）server は、Harness が自分のネイティブツールとしてマウントする外部プログラムまたはサービスです。導入後、モデルは `mcp__github__create_issue` のような名前で、組み込みツールと同じようにそれらを呼び出します。

Harness にはこの種のアーティファクト向けのマニフェスト規約がありません。MCP server は Harness が読み込むパッケージではなく、profile patch のプラグイン行として導入されます。`package.json` の `dsh.hub` 宣言が唯一の情報源であり、カタログはそれを読みます。

## マニフェスト規約

```json
{
  "dsh": {
    "hub": {
      "kind": "mcp-server",
      "mcp": {
        "serverName": "github",
        "transport": "stdio",
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-github"],
        "credentials": [{ "envName": "GITHUB_TOKEN", "required": true }]
      }
    }
  }
}
```

- `serverName` はサーバーのツールを `mcp__<serverName>__<tool>` という名前空間に置きます。`[A-Za-z0-9_-]{1,32}` に一致する必要があります。
- `transport` は `stdio` または `streamable-http` です。stdio サーバーには `command` が必要です（`args` は任意）。HTTP サーバーには `url` が必要です。
- `credentials` はサーバーが必要とするシークレットを POSIX 環境変数名で列挙します。`required` のデフォルトは `false` です。

`dsh.hub.mcp` ブロックだけでも種類の宣言になります。逆に（`kind: "mcp-server"` だけで `mcp` ブロックがない場合）は不完全な宣言として、スキップではなく拒否されます。

## 導入の仕組み

インストールプランは、そのプロファイル自身の `cordis.patch.yml` レイヤーに `@deepseek-ai/dsh-mcp-client` の行（行 id は `mcp-<serverName>`）を 1 行追加します。後から Harness をアップグレードしても上書きされません。

```sh
npx @dsh-fish/cli add <artifact-id> --profile <profile>
```

カタログが保存するのは資格情報の参照だけで、値は保存しません。生成された行では、各シークレットは読み込み時にプロセス環境から解決され（`!!js process.env.GITHUB_TOKEN`）、必須の資格情報はサーバーが動く前に値の入力を求められます。これが、カタログの行を公開して配信できる理由です。
