A profile is an ordered list of bundles that together form a complete, runnable harness composition.

The word names two different things. The artifact on this page is a published bundle list. The `--profile` runtime flag picks which local composition boots: `dsh --profile web` runs the profile stored under `$DSH_HOME/profiles/web`.

Installing a profile artifact means adding its bundles, in order, to a local profile you choose. You then boot that profile with the flag.

## Manifest contract

A package declares a profile through `dsh.profile.bundles`:

```json
{
  "dsh": {
    "profile": {
      "bundles": ["@deepseek-ai/dsh-base", "dsh-hello-plugin"]
    }
  }
}
```

Every profile starts from `@deepseek-ai/dsh-base`, the shared core layer. Later layers win per row. A patch replaces a row's whole config rather than deep-merging it, so order changes the result.

A package that declares both `dsh.profile` and `dsh.bundle` classifies as a profile, because a profile is itself an ordered stack of bundles.

## Install and publish

The install plan adopts a profile bundle by bundle, one add per entry in declared order:

```sh
dsh plugin --profile web add @deepseek-ai/dsh-base
dsh plugin --profile web add dsh-hello-plugin
```

`dsh plugin add` creates the local profile on first use, with `@deepseek-ai/dsh-base` as its first bundle, then appends each further bundle.

To publish, [submit](/docs/submit) the package to dsh.fish. The registry reads the same `dsh.profile.bundles` list.
