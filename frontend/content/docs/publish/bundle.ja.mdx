Bundle は、プラグインを 1 つの patch レイヤーとして Harness に持ち込む npm パッケージで、Harness の機能を配布する標準的な単位です。

## マニフェスト契約

パッケージは `package.json` で `dsh.bundle.patch` を宣言し、Cordis の patch ファイルを指すことで bundle になります。

```json
{
  "name": "dsh-hello-plugin",
  "version": "0.1.0",
  "type": "module",
  "files": ["index.js", "cordis.patch.yml"],
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```

patch ファイルは、そのレイヤーが挿入するプラグイン行を列挙します。宣言が bundle を定義します。宣言のないパッケージは通常の依存として導入できても、Harness はそのレイヤーを有効化せず、dsh.fish のカタログもプラグインとして掲載しません。

## インストールと公開

bundle のインストールプランは、プロファイルへのパッケージ追加 1 回です。

```sh
npx @dsh-fish/cli add dsh-hello-plugin --profile web
# Harness ネイティブの同等コマンド:
dsh plugin --profile web add dsh-hello-plugin
```

npm にはビルド済みコードを公開し、利用者がビルド許可を必要としないようにしてください。git インストールはソースを取得します。自己完結した `prepare` スクリプトを用意し、利用者による許可リストへの追加を前提にしてください。pnpm はインストール時にエージェントのサンドボックスの外でそのスクリプトを実行するからです。

公開するには、パッケージまたはリポジトリを dsh.fish に[提出](/docs/submit)します。レジストリは実際のマニフェストを読み直すので、宣言は公開された `package.json` に存在する必要があります。
