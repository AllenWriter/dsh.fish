MCP（Model Context Protocol）server 是一个外部程序或服务，Harness 把它的工具挂载为自己的原生工具。安装后，模型可以像调用内置工具一样调用它们，工具名形如 `mcp__github__create_issue`。

Harness 没有为这种构件定义清单约定：MCP server 安装为 profile patch 中的一行插件配置，而不是 Harness 直接加载的包。`package.json` 里的 `dsh.hub` 声明是唯一的事实来源，目录读取的就是它。

## 清单约定

```json
{
  "dsh": {
    "hub": {
      "kind": "mcp-server",
      "mcp": {
        "serverName": "github",
        "transport": "stdio",
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-github"],
        "credentials": [{ "envName": "GITHUB_TOKEN", "required": true }]
      }
    }
  }
}
```

- `serverName` 决定服务器工具的命名空间：`mcp__<serverName>__<tool>`。它必须匹配 `[A-Za-z0-9_-]{1,32}`。
- `transport` 为 `stdio` 或 `streamable-http`。stdio server 需要 `command`（`args` 可选）；HTTP server 需要 `url`。
- `credentials` 以 POSIX 环境变量名的形式列出服务器需要的密钥。`required` 默认为 `false`。

单独的 `dsh.hub.mcp` 块本身就声明了类型。反过来（只有 `kind: "mcp-server"` 却没有 `mcp` 块）属于声明残缺，会被拒绝而不是跳过。

## 安装机制

安装计划会在该 profile 自己的 `cordis.patch.yml` 层追加一行 `@deepseek-ai/dsh-mcp-client`（行 id 为 `mcp-<serverName>`），之后升级 Harness 不会覆盖它：

```sh
npx @dsh-fish/cli add <artifact-id> --profile <profile>
```

目录只存凭据引用，不存密钥值。生成的配置行里，每个密钥在加载时从进程环境解析（`!!js process.env.GITHUB_TOKEN`）。每个必需凭据的值都要在服务器运行前填入。

这就是目录行可以公开提供的原因。
