MCP(Model Context Protocol) server는 Harness가 자체 네이티브 도구로 마운트하는 외부 프로그램이나 서비스입니다. 설치 후 모델은 `mcp__github__create_issue` 같은 이름으로 내장 도구와 똑같이 호출합니다.

Harness에는 이런 종류의 아티팩트에 대한 매니페스트 규약이 없습니다. MCP server는 Harness가 직접 읽어들이는 패키지가 아니라 profile patch의 플러그인 행으로 설치됩니다. `package.json`의 `dsh.hub` 선언이 유일한 정보 원본이며 카탈로그는 이것을 읽습니다.

## 매니페스트 규약

```json
{
  "dsh": {
    "hub": {
      "kind": "mcp-server",
      "mcp": {
        "serverName": "github",
        "transport": "stdio",
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-github"],
        "credentials": [{ "envName": "GITHUB_TOKEN", "required": true }]
      }
    }
  }
}
```

- `serverName`은 서버 도구를 `mcp__<serverName>__<tool>` 네임스페이스에 둡니다. `[A-Za-z0-9_-]{1,32}`와 일치해야 합니다.
- `transport`는 `stdio` 또는 `streamable-http`입니다. stdio 서버에는 `command`가 필요하고(`args`는 선택 사항) HTTP 서버에는 `url`이 필요합니다.
- `credentials`는 서버에 필요한 시크릿을 POSIX 환경 변수 이름으로 나열합니다. `required`의 기본값은 `false`입니다.

`dsh.hub.mcp` 블록만으로도 종류가 선언됩니다. 반대로(`kind: "mcp-server"`만 있고 `mcp` 블록이 없는 경우)는 불완전한 선언으로, 건너뛰지 않고 거부됩니다.

## 설치 방식

설치 계획은 해당 프로필 자체의 `cordis.patch.yml` 계층에 `@deepseek-ai/dsh-mcp-client` 행(행 id는 `mcp-<serverName>`)을 하나 추가합니다. 나중에 Harness를 업그레이드하더라도 덮어쓰이지 않습니다.

```sh
npx @dsh-fish/cli add <artifact-id> --profile <profile>
```

카탈로그는 자격 증명 참조만 저장하고 값은 저장하지 않습니다. 생성된 행에서 각 시크릿은 로드 시점에 프로세스 환경에서 해석되고(`!!js process.env.GITHUB_TOKEN`), 필수 자격 증명은 서버가 실행되기 전에 값을 입력해야 합니다.

이것이 카탈로그 행을 공개로 제공할 수 있는 이유입니다.
