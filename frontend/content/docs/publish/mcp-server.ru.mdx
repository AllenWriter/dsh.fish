MCP (Model Context Protocol) server — внешняя программа или сервис, чьи инструменты Harness подключает как собственные нативные инструменты. После установки модель вызывает их как встроенные, с именами вида `mcp__github__create_issue`.

У Harness нет манифест-конвенции для этого вида артефактов: MCP server устанавливается как строка плагина в profile patch, а не как пакет, который Harness загружает. Объявление `dsh.hub` в `package.json` — единственный источник данных, и каталог читает именно его.

## Контракт манифеста

```json
{
  "dsh": {
    "hub": {
      "kind": "mcp-server",
      "mcp": {
        "serverName": "github",
        "transport": "stdio",
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-github"],
        "credentials": [{ "envName": "GITHUB_TOKEN", "required": true }]
      }
    }
  }
}
```

- `serverName` задаёт пространство имён инструментов сервера: `mcp__<serverName>__<tool>`. Оно должно соответствовать `[A-Za-z0-9_-]{1,32}`.
- `transport` — `stdio` или `streamable-http`. Для stdio нужен `command` (`args` необязательны), для HTTP — `url`.
- `credentials` перечисляет нужные серверу секреты как имена POSIX-переменных окружения. `required` по умолчанию `false`.

Блок `dsh.hub.mcp` сам по себе объявляет вид артефакта. Обратное (`kind: "mcp-server"` без блока `mcp`) — неполная декларация, и она отклоняется, а не пропускается.

## Как происходит установка

План установки добавляет одну строку `@deepseek-ai/dsh-mcp-client` (id строки `mcp-<serverName>`) в собственный слой `cordis.patch.yml` профиля, и последующее обновление Harness её не перезапишет.

```sh
npx @dsh-fish/cli add <artifact-id> --profile <profile>
```

Реестр хранит только ссылки на credentials, никогда значения. В сгенерированной строке каждый секрет разрешается при загрузке из окружения процесса (`!!js process.env.GITHUB_TOKEN`), а значение каждого обязательного секрета запрашивается до запуска сервера. Именно поэтому строку каталога можно безопасно отдавать публично.
