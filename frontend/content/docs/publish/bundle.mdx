A bundle is an npm package that carries plugins into the harness as one patch layer. It is the standard unit for distributing harness capabilities.

## Manifest contract

A package becomes a bundle by declaring `dsh.bundle.patch` in its `package.json`, pointing at a Cordis patch file:

```json
{
  "name": "dsh-hello-plugin",
  "version": "0.1.0",
  "type": "module",
  "files": ["index.js", "cordis.patch.yml"],
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```

The patch file lists the plugin rows the layer inserts.

The declaration defines the bundle. A package without it:

- still installs as a plain dependency,
- the harness activates no layer for it, and
- the dsh.fish catalog does not list it as a plugin.

## Install and publish

The install plan for a bundle is one package-manager add into a profile:

```sh
npx @dsh-fish/cli add dsh-hello-plugin --profile web
# harness-native equivalent:
dsh plugin --profile web add dsh-hello-plugin
```

Publish to npm with prebuilt code so users need no build allowance.

A git install fetches sources instead: ship a self-contained `prepare` script. Expect users to allowlist it, because pnpm runs that script at install time outside the agent sandbox.

To publish, [submit](/docs/submit) the package or repository to dsh.fish. The registry re-reads the real manifest, so the declaration must be in the published `package.json`.
