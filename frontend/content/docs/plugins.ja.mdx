DeepSeek Harness はプラグインフレームワークの Cordis 上で動作します。モデルアダプター、ツールレジストリ、セッションログ、エージェントループはすべて、設定からマウントされるプラグインです。書き換えるべき特権的なコアはありません。Harness を拡張するには、ほかのプラグインの隣にプラグインをマウントします。プラグインが登録したものは、アンロード時に破棄されます。

コアが小さく保たれるのはこのためです。新しい機能が欲しいときは、Harness のアップグレードを待つのではなく、プラグインを追加します。

## プラグインになれるもの

dsh.fish のカタログは 6 つのアーティファクト種別を扱います。それぞれに独自のマニフェスト契約があります。

- [Bundle](/docs/publish/bundle)：プロファイルにプラグインの patch レイヤーを追加する npm パッケージ。
- [Skill](/docs/publish/skill)：エージェントが必要に応じて読み込む Markdown 指示ファイル。
- [MCP server](/docs/publish/mcp-server)：ネイティブツールとしてマウントされる外部 Model Context Protocol サーバー。
- [Agent preset](/docs/publish/agent-preset)：セッションに独自のツールとプロンプトを与える 1 つの `agent.cordis.yml`。
- [Profile](/docs/publish/profile)：完全な構成を成す、順序付きの bundle スタック。
- [Hook bridge](/docs/publish/hook-bridge)：既存の Claude Code や Codex のシェルフックを dsh 内で実行するもの。

## 信頼の問題

プラグインは、あなたが Harness に与えた権限で動くコードです。ワークスペース内で動作し、git インストールではエージェントのサンドボックスの外でパッケージのビルドスクリプトが実行されることがあります。README が示すのは作者の主張であり、インストールが実際に行うことではありません。

dsh.fish はこの隙間のためにあります。カタログは各ソースの実際のマニフェストとファイルを読み、各アーティファクトページは、何かを実行する前にインストールプラン（インストールが行うファイル書き込み、パッケージ追加、patch 行）を表示します。まず検査し、それからインストールしてください。

自分でプラグインを作るには、[最初のプラグインを作る](/docs/develop/first-plugin)から始めてください。
