| Term | Meaning |
| --- | --- |
| Agent harness | A program that runs an AI agent: it connects a model to tools and controls what the agent may do. |
| `$DSH_HOME` | The one directory where the harness keeps all user data; defaults to `~/.dsh`. |
| Profile | A named setup under `$DSH_HOME/profiles/<name>` that decides which plugins load. |
| Session | One conversation with the agent, stored as an append-only event log. |

Each term below ends with the page where you actually use it.

## Agent harness

An agent harness is the program that turns an AI model into an agent. It gives the model tools, feeds the results back for the next step, and enforces limits on what the agent may do. DeepSeek Harness is DeepSeek AI's open-source harness, designed so that every capability is a plugin. Used in: [Quickstart](/docs/quickstart).

## `$DSH_HOME`

The harness keeps all user data (profiles, settings, credentials, session logs) under one root directory. It uses the `$DSH_HOME` environment variable when set, otherwise `~/.dsh`. dsh.fish install plans write only under this root or a profile directory inside it. Used in: installs from the [hub plugin](/docs/hub) and the [CLI](/docs/cli).

## Profile

A profile is a directory under `$DSH_HOME/profiles/<name>` holding the plugin packages and patch files that define one harness setup. You choose a profile at launch with `--profile <name>`; the `web` and `headless` profiles are created automatically on first use. dsh.fish installs every plugin into a named profile. Used in: [CLI installs](/docs/cli); [Profiles](/docs/publish/profile) covers publishing one.

## Session

A session is one conversation between you and the agent. The harness stores it as an append-only log of events (messages, tool calls, approvals) and derives what the model sees from that log, so a session can be replayed and resumed. Sessions are grouped by workspace. Used in: the [hub plugin](/docs/hub), which works inside a live session.

## Workspace

A workspace is a project directory you explicitly hand to the harness. The Web UI composer stays locked until you select one, and every session then runs with that directory as its working directory. Treat it as a trust boundary: the default permissions let the agent write anywhere under it, so pick a directory you have reviewed. Used in: [Quickstart](/docs/quickstart), step 3.

## Model and provider

The model is the AI the agent reasons with; the provider is the service that serves the model, such as DeepSeek or another provider you add. You enter the provider's API key once under **Settings → Models**. The key is stored locally in `$DSH_HOME/.credentials.yaml` and is never sent to dsh.fish. Used in: [Quickstart](/docs/quickstart), step 2.

## Permissions

Permissions decide what the agent may do with its tools. They come as named presets: the default `workspace-write` preset confines writes to the workspace (plus a temporary area) and asks you before operations that need approval, while `danger-full-access` removes the sandbox and stops asking. Used in: the permissions note in [Quickstart](/docs/quickstart).

## Plugin

A plugin is the harness's only extension mechanism. The core stays deliberately small; tools, model providers, and approval rules all arrive as plugins listed in a profile. An installed plugin acts with the permissions you gave the harness, which is why dsh.fish lets you inspect what a plugin is and what it will do before you install it. Used in: [Why plugins](/docs/plugins) and [Your first plugin](/docs/develop/first-plugin).
