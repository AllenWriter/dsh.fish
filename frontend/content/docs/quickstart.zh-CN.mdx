本教程带你从空白终端走进一个可用的 DeepSeek Harness 会话，共四步。

DeepSeek Harness（`dsh`）是一个 [agent harness](/docs/concepts)（智能体框架）：它让语言模型带着工具循环工作，模型因此可以读文件、跑命令、改代码。会话（[session](/docs/concepts)）就是你和这个智能体的一段对话。

每个新术语在首次出现时都会链接到核心概念页，那里有完整定义。

API 密钥保存在本机，模型请求不经过 dsh.fish。

## 1. 启动 Web UI

```sh
npx @deepseek-ai/dsh web
```

命令会在 `http://127.0.0.1:3080` 启动 Web UI 并自动打开浏览器。浏览器没打开，就手动访问这个地址。

软件包目前是开发者预览版，用于重要工作前请先阅读 npm 提示和发行说明。

## 2. 连接模型

Harness 需要一个[模型](/docs/concepts)：负责思考的 LLM，由 DeepSeek、Anthropic、OpenAI 这样的供应商提供。

打开 **Settings → Models**，填入供应商的 API 密钥并保存。DeepSeek 卡片只需要密钥；其他供应商从 **Add provider** 添加；公司网关或自建服务走 **Add a custom provider**。

密钥保存在本机的 harness 主目录（`$DSH_HOME`）下，不会传到 dsh.fish。下一次请求直接使用新配置，无需重启。

对于 OpenAI 兼容端点，请逐字核对 base URL 和模型标识。密钥保存成功不代表端点接受所选模型，开始长会话前先跑下面的第一个小任务。

## 3. 选择工作区

[工作区](/docs/concepts)（workspace）是智能体可以查看和修改的项目目录。

点击 **Choose workspace**，打开你要检查的仓库。输入框（composer）在选择工作区之前不可用。

把工作区当作信任边界：智能体在其中读写文件。先审阅仓库，不要打开包含无关密钥的目录。

## 4. 完成第一个任务

先发送一个只读请求：

```text
Summarize this repository and identify its main packages.
```

确认回答提到的文件确实存在。

然后让它做一个可验证的小动作，比如运行一个测试目标。逐项检查它申请的权限和最终 diff。

## 了解权限

[权限](/docs/concepts)决定智能体在哪些操作上可以不经询问直接执行。新会话默认使用 `workspace-write`：智能体可以写入工作区，但这不代表所有读取、进程和网络行为都被隔离。

只批准你理解的操作，把凭据放在工作区之外，提交前审阅修改。

- 用 headless 配置档案在终端里跑自动化任务：`dsh --profile headless "run the tests"` 会运行一个会话、打印最终答案并退出。
