Плагин Hub (`@dsh-fish/hub`) переносит каталог dsh.fish в работающий сеанс. Агент может найти артефакт, показать, что именно сделает установка, и установить его после вашего согласия. Покидать сеанс не нужно.

## Добавьте плагин

```sh
dsh plugin --profile <profile> add @dsh-fish/hub
```

`<profile>` — это профиль, с которым запускается harness: `web` для стандартного лаунчера или тот, который запускает настольная сборка. Опубликованный в npm пакет уже содержит собранный `lib/`, поэтому такая установка не запускает скрипт сборки и не требует записи в `allowBuilds`.

### Local DSH

[Local DSH](https://github.com/stvlynn/local-dsh) запускается с профилем `local-dsh`, а его лаунчер лежит внутри собственной среды выполнения приложения, а не в глобальном `PATH`. Используйте именно этот лаунчер, чтобы плагин попал в профиль, который приложение действительно запускает:

```sh
APP_DATA="$HOME/Library/Application Support/com.localdsh.app"
RUNTIME="$(find "$APP_DATA/runtime" -maxdepth 1 -type d ! -name runtime ! -name '.partial-*' | head -n 1)"
export PATH="$RUNTIME/bin:$PATH"

dsh plugin --profile local-dsh add @dsh-fish/hub
```

Затем перезапустите DSH — инструменты плагина загружаются при старте. Приложение при каждом запуске перезаписывает свой список управляемых bundle, но сохраняет добавленные вами, поэтому плагин остаётся после перезапуска.

### Установка из git

Установка из git — это вариант для разработки, и она должна указывать подкаталог: корень репозитория — это private workspace, а не плагин.

```sh
dsh plugin --profile <profile> add github:stvlynn/dsh.fish#path:packages/dsh-plugin-hub
```

В такой копии нет `lib/`, поэтому сборка выполняется при установке, а pnpm 10 и новее отказывается запускать скрипт сборки, пока вы не разрешите. Скопируйте ключ пакета, который выводит pnpm, в `pnpm-workspace.yaml` вашего профиля и повторите `add`. Это разрешение позволяет коду пакета выполняться на вашей машине во время установки, вне песочницы агента — закрепите commit, чтобы более поздний push не изменил то, что будет запущено.

### Переход с `dsh-hub`

Прежние версии устанавливались из корня репозитория под именем `dsh-hub`:

```sh
dsh plugin --profile <profile> remove dsh-hub
dsh plugin --profile <profile> add @dsh-fish/hub
```

Установки, уже записанные в `$DSH_HOME/.dsh-fish-lock.json`, переименование не затрагивает.

## Проверка

`hub_show` показывает один артефакт подробно, включая точные команды, которые установка выполнит на этой машине. `hub_reviews` анонимно читает оценки сообщества: средний балл по шкале 1–5, распределение и свежие комментарии.

Проверьте оба инструмента, прежде чем разрешить агенту установку. Те же доказательства видны на сайте, если хотите сверить там.

## Установка

`hub_install` применяет план установки на этой машине:

- записывает файлы skill и preset
- добавляет строки MCP и hook в патч-слой профиля
- запускает пакетный менеджер для бандлов

После этого перезапустите harness, чтобы новые строки загрузились.

Если шаг плана собирает пакет из исходников, `hub_install` отказывает, пока вызывающая сторона не передаст `allowBuildScripts: true`. Такой шаг запускает код пакета на вашей машине во время установки, вне песочницы агента, поэтому агент обязан вернуться и спросить вас. Сам он это разрешить не может.

Успешные установки записываются в `$DSH_HOME/.dsh-fish-lock.json`:

- `hub_list` показывает, что установлено на этой машине
- `hub_update` заново применяет текущий план для установленного артефакта
- `hub_remove` откатывает записанную установку (файлы, строки патча, пакеты)

Файл блокировки общий с `@dsh-fish/cli`, поэтому [CLI](/docs/cli) видит те же установки.

## Вход

Вход привязывает установки к вашей учётной записи и открывает `hub_rate`. Чтение каталога не требует входа.

`hub_account` с `action: "login"` начинает OAuth device flow:

- инструмент возвращает короткий код и URL
- вы открываете URL в браузере и подтверждаете вход
- плагин опрашивает сервер, пока вы это делаете

Агент не может подтвердить вход за вас.

Токен записывается в `$DSH_HOME/.dsh-fish-token.json` с правами 0600 и не попадает в логи.

Этот токен намеренно слабее браузерной сессии. Он может читать каталог, разрешать планы установки и оценивать артефакты от вашего имени, но не может публиковать артефакты и заявлять права на них.

## Раздел в настройках

В harness, который отдаёт браузерный клиент, плагин добавляет в настройки раздел **dsh.fish** с тремя вкладками.

- **Browse** ищет по каталогу и показывает план установки артефакта до того, как что-либо выполнится. Пакет, который собирается из исходников, не установится, пока вы не нажмёте кнопку, прямо об этом говорящую.
- **Installed** перечисляет то, что этот профиль установил через хаб, и позволяет это удалить.
- **Account** выполняет вход тем же device flow, показывая код и URL проверки обычной ссылкой.

Это второй интерфейс к тому же установщику, а не второй установщик: раздел обращается к маршрутам того же origin, которые выполняют тот самый код, что и инструменты `hub_*`, и пишут в тот же `$DSH_HOME/.dsh-fish-lock.json`. Поэтому Installed показывает ровно то, о чём сообщает `hub_list`.

Ничего связанного с вашим аккаунтом в браузер не попадает. Device code и сохранённый токен остаются на стороне хоста — именно это позволяет настольному приложению передать ссылку проверки системному браузеру вместо открытия внутри своего окна.

Профиль, не отдающий браузерный клиент, всё равно загружает инструменты.

## Безопасность

Запись файлов ограничена разрешённым `$DSH_HOME`; план, пытающийся выйти за его пределы, отклоняется.

Шаги со сборкой из исходников требуют вашего явного согласия, как описано выше.

У `hub_rate` есть собственное правило: агент оценивает только то, что эта машина действительно установила и использовала, опирается на собственный опыт и сообщает вам, когда оставляет оценку.

## Инструменты

| Инструмент    | Что делает                                                                 |
| ------------- | -------------------------------------------------------------------------- |
| `hub_search`  | Ищет в реестре по тексту и типу артефакта.                                 |
| `hub_show`    | Показывает один артефакт подробно, включая то, что сделает установка.      |
| `hub_install` | Применяет план установки на этой машине.                                   |
| `hub_list`    | Артефакты, которые эта машина установила через hub.                        |
| `hub_remove`  | Откатывает записанную установку (файлы, строки патча, пакеты).             |
| `hub_update`  | Заново применяет текущий план для установленного артефакта.                |
| `hub_account` | Вход через OAuth device flow, проверка статуса, выход.                     |
| `hub_reviews` | Оценки сообщества: шкала 1–5, средний балл, распределение, комментарии.    |
| `hub_rate`    | Оценить установленный артефакт на 1–5 звёзд, можно с публичным отзывом.    |

## Конфигурация

```yaml
- id: hub
  name: '@dsh-fish/hub'
  config:
    baseUrl: https://dsh.fish # при самостоятельном развёртывании меняется только это
    targetProfile: current # или конкретное имя профиля
```
