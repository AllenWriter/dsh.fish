要在 dsh.fish 上架外掛，你提交的是原始碼，不是描述。[提交表單](/submit)把註冊表指向一個 npm 套件或 GitHub 儲存庫，註冊表用爬蟲同款的讀取器去讀真實的 manifest。寫進目錄的內容就是 harness 實際會載入的內容，任何目錄欄位都不能手寫。

## 先登入

提交需要已登入的瀏覽器工作階段。harness 持有的裝置 token 可以搜尋、安裝和評分，但不能替你發佈。未登入時打開 `/submit`，頁面會先請你登入，再帶你回到表單。

## 填寫表單

表單要填類型、來源和一條可選的審核備註。

類型是你認為的來源種類：Bundle、設定檔、技能或 Agent 預設。來源寫作 `npm:<package>` 或 `github:<owner>/<repo>[/<path>]`。備註只有提交進入人工審核時才會被讀到。

## 註冊表檢查什麼

你選的類型只告訴讀取器先查哪個 manifest：技能會先查 `SKILL.md`。它不是證據。註冊表讀到的種類和你選的不一致，提交會被拒絕；完全讀不到 harness manifest 也會被拒絕，比如 Bundle 必須在 package.json 裡宣告 `dsh.bundle`。

## 立即通過或排隊審核

來源可讀、且能證明歸你所有的提交會立即通過。

所有權的含義是：儲存庫擁有者的 id 和你登入的 GitHub 帳戶一致，兩邊按 GitHub 的數字 id 比較，改了使用者名稱也冒認不了。

npm 套件沒有對應的身分檢查；組織的儲存庫歸組織而不是歸你。這兩類都進審核佇列。

通過的提交會直接給出已發佈構件的連結。排隊的提交在維護者審核後出現。構件已被其他帳戶認領時，提交會按衝突拒絕。

## 上架之後

構件建立或 README 變更後，網站按語言排隊產生翻譯。翻譯只在仍與目前 README 相符時提供；待處理、失敗或過期的翻譯一律顯示原文。
