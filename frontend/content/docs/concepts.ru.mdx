| Термин | Значение |
| --- | --- |
| Agent harness | Программа, которая запускает ИИ-агента: подключает модель к инструментам и управляет тем, что агенту разрешено. |
| `$DSH_HOME` | Корневой каталог, где harness хранит все пользовательские данные; по умолчанию `~/.dsh`. |
| Профиль (profile) | Именованная конфигурация в `$DSH_HOME/profiles/<name>`, определяющая, какие плагины загружаются. |
| Сессия (session) | Один разговор с агентом, хранится как журнал событий только на добавление. |
| Рабочая область (workspace) | Каталог проекта, который вы передаёте агенту; ограничивает, куда агент может писать. |
| Модель / провайдер | ИИ, с помощью которого агент рассуждает, и сервис, который его предоставляет; API-ключ остаётся на вашем компьютере. |

| Плагин (plugin) | Единственная единица расширения: любая возможность, встроенная или установленная, — плагин. |

Каждый термин ниже заканчивается ссылкой на страницу, где он реально используется.

## Agent harness

Agent harness — программа, которая превращает ИИ-модель в агента. Она даёт модели инструменты, возвращает их результаты модели для следующего шага и ограничивает то, что агенту разрешено делать.

DeepSeek Harness — открытый harness от DeepSeek AI, спроектированный так, что каждая возможность является плагином.

Где используется: [Быстрый старт](/docs/quickstart).

## `$DSH_HOME`

Harness хранит все пользовательские данные (профили, настройки, учётные данные, журналы сессий) в одном корневом каталоге. Если задана переменная окружения `$DSH_HOME`, используется она, иначе `~/.dsh`.

Планы установки dsh.fish пишут только в этот корень или в каталог профиля внутри него.

Где используется: установки через [плагин Hub](/docs/hub) и [CLI](/docs/cli).

## Профиль (profile)

Профиль — каталог в `$DSH_HOME/profiles/<name>`, содержащий пакеты плагинов и файлы исправлений, которые определяют одну конфигурацию harness. Профиль выбирается при запуске флагом `--profile <name>`; профили `web` и `headless` создаются автоматически при первом использовании.

dsh.fish устанавливает каждый плагин в указанный профиль.

Где используется: [установка через CLI](/docs/cli); о публикации профиля рассказывает страница [формата profile](/docs/publish/profile).

## Сессия (session)

Сессия — один разговор между вами и агентом. Harness хранит её как журнал событий только на добавление (сообщения, вызовы инструментов, подтверждения), а то, что видит модель, выводится из этого журнала, поэтому сессию можно воспроизвести и продолжить.

Сессии группируются по рабочим областям.

Где используется: [плагин Hub](/docs/hub), работающий внутри активной сессии.

## Рабочая область (workspace)

Рабочая область — каталог проекта, который вы явно передаёте harness. Пока она не выбрана, поле ввода веб-интерфейса заблокировано; после выбора каждая сессия работает с этим каталогом как рабочим.

Относитесь к ней как к границе доверия: разрешения по умолчанию позволяют агенту писать в любое место внутри неё, поэтому выбирайте проверенный каталог.

Где используется: [Быстрый старт](/docs/quickstart), шаг 3.

## Модель и провайдер

Модель — ИИ, с помощью которого агент рассуждает; провайдер — сервис, который её предоставляет, например DeepSeek или другой добавленный вами провайдер. API-ключ провайдера вводится один раз в **Settings → Models**.

Ключ хранится локально в `$DSH_HOME/.credentials.yaml` и никогда не отправляется в dsh.fish.

Где используется: [Быстрый старт](/docs/quickstart), шаг 2.

## Разрешения (permissions)

Разрешения определяют, что агент может делать с инструментами.

Они предоставляются как именованные пресеты: пресет по умолчанию `workspace-write` ограничивает запись рабочей областью (плюс временный каталог) и спрашивает вас перед операциями, требующими подтверждения. `danger-full-access` убирает песочницу и перестаёт спрашивать.

Где используется: примечание о разрешениях в [Быстром старте](/docs/quickstart).

## Плагин (plugin)

Плагин — единственный механизм расширения harness. Ядро намеренно остаётся маленьким; инструменты, провайдеры моделей и правила подтверждения загружаются как плагины, перечисленные в профиле.

Установленный плагин действует с разрешениями, которые вы дали harness, поэтому dsh.fish позволяет проверить, что представляет собой плагин и что он будет делать, до установки.

Где используется: [Зачем нужны плагины](/docs/plugins) и [Ваш первый плагин](/docs/develop/first-plugin).
