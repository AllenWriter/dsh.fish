DeepSeek Harness работает на Cordis, плагинном фреймворке. Адаптер модели, реестр инструментов, журнал сессии и агентный цикл — всё это плагины, подключаемые из конфигурации. Привилегированного ядра, которое нужно править, нет: чтобы расширить Harness, подключите плагин рядом с остальными; всё зарегистрированное плагином освобождается при его выгрузке.

Поэтому ядро остаётся небольшим. Когда нужна новая возможность, вы добавляете плагин, а не ждёте обновления Harness.

## Из чего может состоять плагин

Каталог dsh.fish охватывает шесть видов артефактов. У каждого свой манифест-контракт:

- [Bundle](/docs/publish/bundle): npm-пакет, добавляющий в профиль слой patch с плагинами.
- [Skill](/docs/publish/skill): Markdown-файл с инструкциями, который агент загружает по мере нужды.
- [MCP server](/docs/publish/mcp-server): внешний сервер Model Context Protocol, подключаемый как нативные инструменты.
- [Agent preset](/docs/publish/agent-preset): один `agent.cordis.yml`, дающий сессии собственные инструменты и промпт.
- [Profile](/docs/publish/profile): упорядоченный стек bundle, образующий законченную композицию.
- [Hook bridge](/docs/publish/hook-bridge): запускает существующие shell-хуки Claude Code или Codex внутри dsh.

## Проблема доверия

Плагин — это код, работающий с разрешениями, которые вы выдали Harness. Он действует внутри вашей рабочей области, а при установке из git может запустить скрипт сборки пакета вне песочницы агента. README говорит лишь о том, что заявляет автор, а не о том, что установка сделает на самом деле.

dsh.fish существует ради этого разрыва. Каталог читает реальные манифест и файлы каждого источника, а каждая страница артефакта показывает план установки (файлы, пакеты и строки patch, которые выполнит установка) до того, как вы что-либо запустите. Сначала проверка, потом установка.

Чтобы написать собственный плагин, начните с [Создайте первый плагин](/docs/develop/first-plugin).
