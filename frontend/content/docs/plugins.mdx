DeepSeek Harness runs on Cordis, a plugin framework. The model adapter, the tool registry, the session log, and the agent loop are all plugins mounted from configuration.

There is no privileged core to patch: you extend the harness by mounting a plugin beside the others. Whatever a plugin registers is disposed when it unloads.

That is why the core stays small. When you want a new capability, you add a plugin; you do not wait for a harness upgrade.

## What a plugin can be

dsh.fish catalogs four artifact kinds. Each has its own manifest contract:

- [Bundle](/docs/publish/bundle): an npm package that adds a patch layer of plugins to a profile.
- [Skill](/docs/publish/skill): a Markdown file of instructions the agent loads on demand.
- [Agent preset](/docs/publish/agent-preset): one `agent.cordis.yml` that gives a session its own tools and prompt.
- [Profile](/docs/publish/profile): an ordered stack of bundles that forms a complete composition.

## The trust problem

A plugin is code that runs with the permissions you granted the harness.

It acts inside your workspace. A git install can run the package's build script outside the agent sandbox.

A README tells you what the author claims, not what installing would do.

dsh.fish exists for that gap.

The catalog reads each source's real manifest and files. Every artifact page shows the install plan (the files and packages an install would run) before you run anything.

Inspect first, then install.

To build a plugin of your own, start with [Build your first plugin](/docs/develop/first-plugin).
