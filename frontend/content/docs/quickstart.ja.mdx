このチュートリアルでは、空のターミナルから DeepSeek Harness のセッションまで 4 つの手順で進みます。

DeepSeek Harness（`dsh`）は[エージェントハーネス](/docs/concepts)です。言語モデルがツールを持ってループで動作し、ファイルの読み取り、コマンドの実行、コードの編集を代行します。[セッション](/docs/concepts)とは、そのエージェントとの一回の会話です。

新しい用語は初出の場所から基本概念ページにリンクしています。

API キーはローカルに保存され、モデルへのリクエストは dsh.fish を経由しません。

## 1. Web UI を起動する

```sh
npx @deepseek-ai/dsh web
```

このコマンドは `http://127.0.0.1:3080` で Web UI を起動し、ブラウザで開きます。ブラウザが開かない場合は、そのアドレスに手動でアクセスしてください。

このパッケージは開発者プレビュー版です。重要な作業に使う前に、npm のプロンプトとリリースノートを確認してください。

## 2. モデルを接続する

Harness には[モデル](/docs/concepts)が必要です。モデルは思考を担当する LLM で、DeepSeek、Anthropic、OpenAI などのプロバイダーが提供します。

**Settings → Models** を開き、プロバイダーの API キーを入力して保存します。DeepSeek のカードはキーだけで足ります。他のプロバイダーは **Add provider** から、社内ゲートウェイや自前のサーバーは **Add a custom provider** から追加します。

キーはマシン上の harness ホームディレクトリ（`$DSH_HOME`）に保存され、dsh.fish には送信されません。次のリクエストから新しい設定が使われ、再起動は不要です。

OpenAI 互換エンドポイントでは、base URL とモデル識別子を一字ずつ確認してください。キーの保存に成功しても、エンドポイントがそのモデルを受け付けるとは限りません。長いセッションの前に、下の小さな最初のタスクを実行してください。

## 3. ワークスペースを選ぶ

[ワークスペース](/docs/concepts)は、エージェントが閲覧と変更を許可されるプロジェクトディレクトリです。

**Choose workspace** を選び、調べたいリポジトリを開きます。ワークスペースを選ぶまで、composer（下部のメッセージ入力欄）は使えません。

ワークスペースは信頼境界として扱ってください。エージェントはその中で読み書きします。先にリポジトリを確認し、無関係な秘密情報を含むディレクトリは開かないでください。

## 4. 最初のタスクを実行する

まず読み取り専用のリクエストを送ります。

```text
Summarize this repository and identify its main packages.
```

回答に出たファイルが実在することを確かめます。

次に、テストを一つ実行するような、検証できる小さな操作を頼みます。要求された権限と最終的な diff を一つずつ確認してください。

## 権限を理解する

[権限](/docs/concepts)は、エージェントが確認なしで実行してよい操作を決めます。新しいセッションは `workspace-write` で始まります。エージェントはワークスペース内に書き込めますが、すべての読み取り、プロセス、ネットワーク動作が隔離されるわけではありません。

理解した操作だけを承認し、認証情報はワークスペースの外に置き、コミット前に変更を確認してください。
