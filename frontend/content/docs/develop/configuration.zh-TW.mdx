設定是外掛程式公共契約的一部分。用明確的錯誤拒絕無效值，不要用靜默預設值把問題蓋過去。

## 定義並驗證設定

匯出一個 `Config` 型別和一個同名的 Schemastery schema，把預設值直接寫在 schema 欄位上。外掛程式載入時，harness 會用這個 schema 驗證使用者設定；無效值會讓載入失敗，並給出可處理的錯誤訊息。

```ts
import type { Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'

export const name = 'my-plugin'

export interface Config {
  greeting: string
  maxRetries: number
}

export const Config: Schema<Config> = Schema.object({
  greeting: Schema.string().default('Hello'),
  maxRetries: Schema.number().default(3),
})

export function apply(ctx: Context, config: Config) {
  console.log(config.greeting)  // User value or schema default.
}
```

設定裡不要放秘密值：設定只攜帶參照，例如 `apiKeyEnv: DEEPSEEK_API_KEY`，外掛程式在需要時透過 `ctx.credentials` 解析出真正的值。

測試缺少欄位、錯誤型別，以及每個邊界上的取值。

## 理解組合順序

harness 在空的根設定上按以下順序疊加出有效設定：

1. 配置檔案的 `dsh.profile.bundles` 清單中每個套件（bundle）的 patch，按清單順序；
2. 配置檔案自己的 `cordis.patch.yml`；
3. home 級 `$DSH_HOME/cordis.patch.yml`；
4. 每個 `--patch <path>` overlay，按命令列順序。

後面的層按列勝出：patch 會整列替換 `config` 的值，而不是按鍵深度合併。當某個覆寫看起來消失時，dump 出解析後的設定：

```sh
dsh --profile demo --dump-config
```

對配置檔案級和 home 級 patch 檔案的修改會熱重載；新增、移除或更新套件則需要重新啟動。

## 封裝編譯產物

只發布執行時需要的檔案：

- 編譯產物
- manifest
- README
- 授權

測試打出來的真實 tarball，而不是工作目錄：

```sh
pnpm pack
dsh plugin --profile demo add ./hello-plugin-0.1.0.tgz
```

從 Git 安裝拿到的是原始碼而不是建置產物，所以套件需要一個能在安裝後建置入口檔案的 `prepare` 腳本。pnpm 10 及以上版本預設拒絕執行 git 相依的 `prepare`，使用者需要先在配置檔案的 `pnpm-workspace.yaml` 裡明確允許：

```yaml
allowBuilds:
  dsh-hello-plugin: true
```

這個腳本在使用者機器上執行，不在任何代理沙箱之內。

讓它保持可重現，寫清楚它的行為，並建議使用者固定 commit（`github:you/hello-plugin#<sha>`）。

## 發布檢查清單

- 裝進一個乾淨的測試配置檔案。
- dump 並檢查解析後的設定列。
- 走一遍成功、驗證失敗和 dispose 三條路徑。
- 套件變更後重新啟動；只有 patch 編輯可以依賴熱重載。
- 移除外掛程式，確認沒有留下檔案、工具或背景資源。

套件準備好後，選擇對應的 [dsh.fish 發布格式](/docs/publish/bundle)並[提交原始碼](/docs/submit)。
