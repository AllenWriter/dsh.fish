## Start from the source checkout

The current official development flow runs from a DeepSeek Harness source checkout. Complete its run-from-source setup first, then create a scratch directory at the repository root:

```sh
mkdir -p scratch-plugin/src
```

Create `scratch-plugin/src/my-plugin.ts`:

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'hello-plugin'

export function apply(ctx: Context): void {
  console.log('[hello-plugin] plugin loaded!')
}
```

## Load the source overlay

Run `pwd`, then create `scratch-plugin/cordis.yml`. Replace the example root with the absolute source-checkout path:

```yaml
- insert:
    - id: hello
      name: '/absolute/path/to/deepseek-harness/scratch-plugin/src/my-plugin.ts'
```

Start the Web UI with the overlay:

```sh
pnpm dsh web --patch ./scratch-plugin/cordis.yml
```

Open `http://127.0.0.1:3080` and confirm that the terminal prints the plugin-loaded line. The absolute path matters: a patch contributes configuration but does not change the directory used to resolve modules.

## Development loop

Capabilities registered through `ctx` are effects and are removed when the plugin unloads. Use `ctx.effect()` with an explicit disposer for resources such as a timer or network connection. Source-overlay edits can hot-reload; adding, removing, or rebuilding a bundle normally requires a restart.
