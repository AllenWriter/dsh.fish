---
title: Build your first plugin
description: Create a minimal DeepSeek Harness plugin, load it with a source overlay, and watch it run in the Web UI.
---

DeepSeek Harness is composed from plugins. A plugin is a TypeScript module that exports an `apply` function. When the harness loads the plugin it calls `apply` and hands it a Cordis context, the object through which the plugin registers everything it adds.

This tutorial builds the smallest possible plugin, loads it into the Web UI, and removes it again. The flow runs from a DeepSeek Harness source checkout, so complete the official run-from-source setup first.

## Create the plugin

From the repository root, create a scratch directory:

```sh
mkdir -p scratch-plugin/src
```

Create `scratch-plugin/src/my-plugin.ts`:

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'hello-plugin'

export function apply(ctx: Context): void {
  console.log('[hello-plugin] plugin loaded!')
}
```

Everything registered through `ctx` is an effect: the harness undoes it automatically when the plugin unloads, so nothing leaks between loads.

## Load it with a source overlay

A source overlay is a patch file that inserts your plugin into the composed configuration without editing the profile itself.

Run `pwd`, then create `scratch-plugin/cordis.yml`, replacing the example root with the absolute checkout path:

```yaml
- insert:
    - id: hello
      name: '/absolute/path/to/deepseek-harness/scratch-plugin/src/my-plugin.ts'
```

The path must be absolute. A patch contributes configuration, but it does not change the directory the loader resolves modules from.

Start the Web UI with the overlay:

```sh
pnpm dsh web --patch ./scratch-plugin/cordis.yml
```

## Verify in the Web UI

Open `http://127.0.0.1:3080`. The terminal prints `[hello-plugin] plugin loaded!` during startup. Send a message and watch the run: the Web UI lists each step, including the model's Think row and every tool call with its input and output.

## Iterate and remove

Edit the plugin, save, and check the result again. Edits to the profile and home `cordis.patch.yml` files hot-reload; adding, removing, or rebuilding an installed bundle requires a restart.

For a resource the context does not manage, such as a timer or a network connection, acquire it inside `ctx.effect()` and return a disposer. The harness runs the disposer when the plugin unloads.

To remove the plugin, stop the command and restart without `--patch`. Its registrations disappear with it.
