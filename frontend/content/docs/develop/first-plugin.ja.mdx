---
title: 最初のプラグインを作る
description: 最小の DeepSeek Harness プラグインを作成し、ソース overlay で読み込み、Web UI で動作を確認します。
---

DeepSeek Harness はプラグインで構成されています。

プラグインとは `apply` 関数をエクスポートする TypeScript モジュールです。harness はプラグインの読み込み時に `apply` を呼び、Cordis context を渡します。プラグインが登録するものはすべてこのオブジェクトを通ります。

このチュートリアルでは最小のプラグインを作り、Web UI に読み込み、最後に取り除きます。手順は DeepSeek Harness のソース checkout 上で実行するので、先に公式の run-from-source セットアップを済ませてください。

## プラグインを作る

リポジトリのルートで作業用ディレクトリを作ります。

```sh
mkdir -p scratch-plugin/src
```

`scratch-plugin/src/my-plugin.ts` を作成します。

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'hello-plugin'

export function apply(ctx: Context): void {
  console.log('[hello-plugin] plugin loaded!')
}
```

`ctx` を通して登録したものはすべて effect です。プラグインのアンロード時に harness が自動で取り消すので、読み込みの間で残りません。

## ソース overlay で読み込む

ソース overlay は、プロファイル本体を編集せずにプラグインを構成へ挿入する patch ファイルです。

`pwd` を実行し、`scratch-plugin/cordis.yml` を作成します。例のパスは checkout の絶対パスに置き換えてください。

```yaml
- insert:
    - id: hello
      name: '/absolute/path/to/deepseek-harness/scratch-plugin/src/my-plugin.ts'
```

パスは絶対パスである必要があります。patch は設定を足すだけで、ローダーがモジュールを解決するディレクトリは変わりません。

overlay を指定して Web UI を起動します。

```sh
pnpm dsh web --patch ./scratch-plugin/cordis.yml
```

## Web UI で確認する

`http://127.0.0.1:3080` を開きます。起動時にターミナルへ `[hello-plugin] plugin loaded!` と表示されます。

メッセージを送って実行を見てみましょう。Web UI には各ステップが並び、モデルの Think 行や、入出力を伴うツール呼び出しも確認できます。

## 反復と削除

プラグインを編集して保存し、結果をもう一度確認します。プロファイルと home の `cordis.patch.yml` への編集はホットリロードされます。インストール済みバンドルの追加、削除、再ビルドには再起動が必要です。

タイマーやネットワーク接続のように context が管理しないリソースは、`ctx.effect()` の中で取得して disposer を返します。harness はプラグインのアンロード時にその disposer を実行します。

プラグインを取り除くには、コマンドを止めて `--patch` なしで再起動します。登録はプラグインと一緒に消えます。
