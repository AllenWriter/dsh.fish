설정은 플러그인의 공개 계약의 일부입니다. 잘못된 값은 분명한 오류로 거부하고, 조용한 기본값으로 문제를 가리지 마세요.

## 설정 정의와 검증

`Config` 타입과 같은 이름의 Schemastery 스키마를 export하고, 기본값은 스키마 필드에 직접 씁니다. 플러그인이 로드될 때 harness가 이 스키마로 사용자 설정을 검증하며, 잘못된 값은 로드를 실패시키고 조치 가능한 오류를 냅니다.

```ts
import type { Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'

export const name = 'my-plugin'

export interface Config {
  greeting: string
  maxRetries: number
}

export const Config: Schema<Config> = Schema.object({
  greeting: Schema.string().default('Hello'),
  maxRetries: Schema.number().default(3),
})

export function apply(ctx: Context, config: Config) {
  console.log(config.greeting)  // User value or schema default.
}
```

설정 값에 비밀을 넣지 마세요. 설정은 `apiKeyEnv: DEEPSEEK_API_KEY` 같은 참조만 담고, 플러그인은 필요할 때 `ctx.credentials`로 값을 확인합니다.

누락된 필드, 잘못된 타입, 각 경계의 값을 테스트하세요.

## 구성 순서 이해하기

harness는 빈 루트 위에 다음 순서로 유효한 설정을 쌓습니다.

1. 프로필의 `dsh.profile.bundles` 목록에 있는 각 번들의 patch (목록 순서)
2. 프로필 자체의 `cordis.patch.yml`
3. home 수준의 `$DSH_HOME/cordis.patch.yml`
4. 각 `--patch <path>` overlay (인자 순서)

뒤의 레이어가 행 단위로 이깁니다. patch는 행의 `config` 값 전체를 교체하며 키 단위 deep merge는 하지 않습니다. 덮어쓰기가 사라진 것처럼 보이면 확인된 설정을 덤프하세요.

```sh
dsh --profile demo --dump-config
```

프로필과 home의 patch 파일 수정은 핫 리로드됩니다. 번들을 추가, 제거, 업데이트할 때는 재시작이 필요합니다.

## 빌드 결과물 패키징

런타임에 필요한 파일만 배포하세요.

- 빌드 결과물
- manifest
- README
- license

작업 트리가 아니라 실제로 만든 tarball을 시험하세요.

```sh
pnpm pack
dsh plugin --profile demo add ./hello-plugin-0.1.0.tgz
```

Git에서 설치하면 빌드 결과물이 아니라 소스를 가져오므로, 설치 후 엔트리 포인트를 빌드하는 `prepare` 스크립트가 필요합니다. pnpm 10 이상은 git 의존성의 `prepare`를 기본으로 실행하지 않으며, 사용자가 프로필의 `pnpm-workspace.yaml`에서 명시적으로 허용해야 합니다.

```yaml
allowBuilds:
  dsh-hello-plugin: true
```

이 스크립트는 사용자 머신에서, 에이전트 샌드박스 밖에서 실행됩니다.

결정적으로 유지하고, 동작을 문서화하고, commit 고정(`github:you/hello-plugin#<sha>`)을 권장하세요.

## 릴리스 체크리스트

- 깨끗한 테스트 프로필에 설치합니다.
- 확인된 설정 행을 덤프해 살펴 봅니다.
- 성공, 검증 실패, dispose 경로를 각각 시험합니다.
- 번들 변경 후에는 재시작하고, 핫 리로드에 기대는 것은 patch 편집뿐입니다.
- 플러그인을 제거하고 파일, 도구, 백그라운드 리소스가 남지 않았는지 확인합니다.

패키지가 준비되면 맞는 [dsh.fish 배포 형식](/docs/publish/bundle)을 고르고 [소스를 제출](/docs/submit)하세요.

공식 참고: [Plugin configuration](https://deepseek-harness.github.io/deepseek-harness/en/develop/basic/config/) 및 [Package and install a plugin](https://deepseek-harness.github.io/deepseek-harness/en/develop/basic/publish/)
