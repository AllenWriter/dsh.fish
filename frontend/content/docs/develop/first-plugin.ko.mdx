DeepSeek Harness는 플러그인으로 이루어져 있습니다.

플러그인은 `apply` 함수를 export하는 TypeScript 모듈입니다. harness는 플러그인을 불러올 때 `apply`를 호출하면서 Cordis context를 넘기고, 플러그인이 등록하는 모든 것이 이 객체를 거칩니다.

이 튜토리얼에서는 가장 작은 플러그인을 만들어 Web UI에 불러온 뒤 다시 제거합니다. 과정은 DeepSeek Harness 소스 checkout에서 진행하므로, 먼저 공식 소스 실행 설정을 마치세요.

## 플러그인 만들기

저장소 루트에서 작업용 디렉터리를 만듭니다.

```sh
mkdir -p scratch-plugin/src
```

`scratch-plugin/src/my-plugin.ts`를 만듭니다.

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'hello-plugin'

export function apply(ctx: Context): void {
  console.log('[hello-plugin] plugin loaded!')
}
```

`ctx`를 통해 등록한 것은 모두 effect입니다. 플러그인을 언로드하면 harness가 자동으로 되돌리므로 불러오기 사이에 남는 것이 없습니다.

## 소스 overlay로 불러오기

소스 overlay는 프로필 자체를 수정하지 않고 플러그인을 구성에 삽입하는 patch 파일입니다.

`pwd`를 실행한 뒤 `scratch-plugin/cordis.yml`을 만들고, 예시 경로를 checkout의 절대 경로로 바꾸세요.

```yaml
- insert:
    - id: hello
      name: '/absolute/path/to/deepseek-harness/scratch-plugin/src/my-plugin.ts'
```

경로는 절대 경로여야 합니다. patch는 설정을 더할 뿐, 로더가 모듈을 찾는 디렉터리를 바꾸지는 않습니다.

overlay를 지정해 Web UI를 시작합니다.

```sh
pnpm dsh web --patch ./scratch-plugin/cordis.yml
```

## Web UI에서 확인하기

`http://127.0.0.1:3080`을 엽니다. 시작하는 동안 터미널에 `[hello-plugin] plugin loaded!`가 출력됩니다.

메시지를 전송하고 실행을 살펴 봅니다. Web UI에는 각 단계가 차례로 표시되고, 모델의 Think 행과 입력·출력이 있는 도구 호출도 볼 수 있습니다.

## 반복과 제거

플러그인을 수정하고 저장한 뒤 결과를 다시 확인하세요. 프로필과 home의 `cordis.patch.yml` 수정은 핫 리로드되고, 설치된 번들을 추가·제거·재빌드할 때는 재시작이 필요합니다.

타이머나 네트워크 연결처럼 context가 관리하지 않는 리소스는 `ctx.effect()` 안에서 얻고 disposer를 반환하세요. harness는 플러그인을 언로드할 때 그 disposer를 실행합니다.

플러그인을 제거하려면 명령을 멈추고 `--patch` 없이 다시 시작하면 됩니다. 등록도 플러그인과 함께 사라집니다.
