도구는 모델이 요청할 수 있는 연산입니다.

하나의 분명한 결과에 집중하고, 모든 입력을 검증하고, 유용한 근거를 반환하며, 숨은 부작용을 피하세요.

## 도구 정의하기

기본 형태는 안정적인 이름, 평이한 설명, 스키마, 비동기 핸들러입니다. 아래 예제는 [첫 플러그인 만들기](/docs/develop/first-plugin)의 스크래치 플러그인을 확장합니다.

```ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(
    defineTool({
      name: 'greet',
      description: 'Greet someone by name.',
      parameters: {
        name: {
          type: 'string',
          required: true,
          description: 'The name to greet',
        },
      },
      output: {
        schema: { type: 'string' },
        render: (_args, value) => [{ type: 'text', text: value }],
      },
      async execute(args) {
        return `Hello, ${args.name}!`
      },
    }),
  )
}
```

`inject`는 플러그인이 필요로 하는 서비스를 선언합니다. 프레임워크는 각 서비스가 준비될 때까지 `apply` 실행을 기다리므로 여기서 `ctx.tools`를 쓸 수 있습니다.

`defineTool`은 `parameters`로부터 `args`를 추론하고 검증합니다.

`execute`는 `output.schema`가 선언한 값을 반환하고, `output.render`가 그 값을 모델이 보는 콘텐츠로 변환합니다.

`apply(ctx)` 안에서 등록하세요. `ctx`를 통한 등록은 effect이므로 플러그인을 언로드하면 도구도 제거됩니다.

## 양쪽에서 검증하기

1. 정상, 빈 값, 잘못된 입력으로 핸들러를 테스트합니다.
2. overlay와 함께 Web UI를 시작하고 `Use the greet tool to greet Ada.`를 전송합니다.
3. 어시스턴트의 답변만이 아니라 도구 행의 입력과 출력을 확인합니다.
4. 플러그인을 제거하고 도구가 사라지는지 확인합니다.

API 키를 도구 인수나 결과에 넣지 마세요. 각 연산 시작 시 `ctx.credentials`로 관리되는 자격 증명을 확인하고, 로그에서는 비밀 값을 가리세요.

공식 참고: [Build a tool](https://deepseek-harness.github.io/deepseek-harness/en/develop/basic/tool/)
