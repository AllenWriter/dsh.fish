---

ツールはモデルが要求できる操作です。

一つの明確な結果に絞り、すべての入力を検証し、有用な証拠を返し、隠れた副作用を避けます。

## ツールを定義する

基本の形は、安定した名前、平易な説明、スキーマ、非同期ハンドラーです。次の例は[最初のプラグインを作る](/docs/develop/first-plugin)のスクラッチプラグインを拡張します。

```ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(
    defineTool({
      name: 'greet',
      description: 'Greet someone by name.',
      parameters: {
        name: {
          type: 'string',
          required: true,
          description: 'The name to greet',
        },
      },
      output: {
        schema: { type: 'string' },
        render: (_args, value) => [{ type: 'text', text: value }],
      },
      async execute(args) {
        return `Hello, ${args.name}!`
      },
    }),
  )
}
```

`inject` はプラグインが必要とするサービスを宣言します。フレームワークは各サービスがそろうまで `apply` の実行を待つので、ここでは `ctx.tools` が使えます。

`defineTool` は `parameters` から `args` を推論して検証します。

`execute` は `output.schema` が宣言した値を返し、`output.render` がその値をモデル向けのコンテンツに変換します。

`apply(ctx)` の中で登録します。`ctx` 経由の登録は effect なので、プラグインをアンロードするとツールも消えます。

## 両側から検証する

1. 正常、空、不正な入力でハンドラーをテストします。
2. overlay 付きで Web UI を起動し、`Use the greet tool to greet Ada.` と送ります。
3. アシスタントの返答だけでなく、ツール行の入力と出力を確認します。
4. プラグインを削除し、ツールが消えることを確認します。

API キーをツールの引数や結果に入れないでください。各操作の開始時に `ctx.credentials` で管理資格情報を解決し、ログでは秘匿します。
