Настройки — часть публичного контракта плагина. Отклоняйте неверные значения ясной ошибкой, а не прячьте проблему за неявным значением по умолчанию.

## Определите и проверьте настройки

Экспортируйте тип `Config` и одноимённую схему Schemastery, значения по умолчанию пишите прямо в полях схемы. При загрузке плагина harness проверяет пользовательские настройки по этой схеме; неверное значение рушит загрузку с понятной ошибкой.

```ts
import type { Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'

export const name = 'my-plugin'

export interface Config {
  greeting: string
  maxRetries: number
}

export const Config: Schema<Config> = Schema.object({
  greeting: Schema.string().default('Hello'),
  maxRetries: Schema.number().default(3),
})

export function apply(ctx: Context, config: Config) {
  console.log(config.greeting)  // User value or schema default.
}
```

Не храните секреты в значениях настроек: настройки содержат только ссылку, например `apiKeyEnv: DEEPSEEK_API_KEY`, а значение плагин разрешает через `ctx.credentials`, когда оно нужно.

Проверьте отсутствующие поля, неверные типы и значения на каждой границе.

## Разберитесь в порядке композиции

Harness собирает итоговую конфигурацию поверх пустого корня в таком порядке:

1. patch каждого бандла из списка `dsh.profile.bundles` профиля, в порядке списка;
2. собственный `cordis.patch.yml` профиля;
3. домашний `$DSH_HOME/cordis.patch.yml`;
4. каждый `--patch <path>` overlay, в порядке аргументов.

Поздний слой выигрывает построчно: patch заменяет всё значение `config` строки, а не сливает ключи. Если переопределение будто исчезло, выгрузите разрешённую конфигурацию:

```sh
dsh --profile demo --dump-config
```

Правки patch-файлов профиля и home применяются горячей перезагрузкой; добавление, удаление или обновление бандла требуют перезапуска.

## Упакуйте сборку

Публикуйте только файлы, нужные во время выполнения:

- сборку
- manifest
- README
- license

Тестируйте реальный tarball, а не рабочее дерево:

```sh
pnpm pack
dsh plugin --profile demo add ./hello-plugin-0.1.0.tgz
```

При установке из Git приходят исходники, а не артефакты сборки, поэтому пакету нужен скрипт `prepare`, который собирает точки входа после установки. pnpm 10 и новее не запускает `prepare` git-зависимости по умолчанию; пользователь должен явно разрешить это в `pnpm-workspace.yaml` профиля:

```yaml
allowBuilds:
  dsh-hello-plugin: true
```

Этот скрипт выполняется на машине пользователя, вне песочницы агента.

Держите его воспроизводимым, документируйте поведение и рекомендуйте фиксировать commit (`github:you/hello-plugin#<sha>`).

## Чек-лист релиза

- Установите в чистый тестовый профиль.
- Выгрузите и изучите разрешённые строки конфигурации.
- Пройдите пути успеха, ошибки валидации и dispose.
- Перезапускайте после изменений бандла; на горячую перезагрузку полагайтесь только при правках patch.
- Удалите плагин и убедитесь, что не осталось файлов, инструментов и фоновых ресурсов.

Когда пакет готов, выберите подходящий [формат публикации dsh.fish](/docs/publish/bundle) и [отправьте исходники](/docs/submit).

Официальные справочники: [Plugin configuration](https://deepseek-harness.github.io/deepseek-harness/en/develop/basic/config/) и [Package and install a plugin](https://deepseek-harness.github.io/deepseek-harness/en/develop/basic/publish/)
