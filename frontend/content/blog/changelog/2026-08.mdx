This is the first changelog post on this site. It covers what actually shipped to dsh.fish through 29 August 2026, not a roadmap. Uncommitted work is not listed.

![The catalog now feeds human, install-client, web, and agent-facing surfaces from shared sources.](/blog/diagrams/hub-surfaces.svg)

## Product docs left the single page

`/docs` is no longer one React page with kind tabs. It is a Fumadocs section: MDX compiled at build time, six locales, in-column sidebar, live scoring tables that call `GET /api/v1/scoring` instead of pasting weights. Guides cover quickstart, concepts, each publish format, the CLI, the hub plugin, submit, scoring, and the REST API.

Search for that tree is `/docs/search`, not `/api/search` — `/api/*` is Hono. Agents can fetch any guide as markdown (`/docs/cli.md`, or `Accept: text/markdown`). `/docs/llms.txt` is generated from the same page tree.

## The hub plugin is an npm package

`@dsh-fish/hub` publishes to npm and loads as a Cordis plugin inside a live session. It searches the catalog, installs from a browse card, opens a README, and talks to the same install plans the website shows. Device login was fixed so a browser Authorize actually redeems the token the plugin is polling for.

Settings register through the harness’s plugin settings client. The plugin is pinned to npm 11 for trusted publishing.

## Catalog taxonomy got smaller, on purpose

`mcp-server` and `hook-bridge` are no longer kinds. Those URLs 301 onto `/browse`. Their old publish guides 301 onto `/docs/plugins`. The remaining four kinds are the ones the harness actually loads: bundle, skill, agent preset, profile.

Categories were aligned with [awesome-dsh-plugin.com](https://awesome-dsh-plugin.com). Topic landings (`/for/...`) exist for a short list of intents and stay `noindex` when they have fewer than three rows.

## Agent-facing surface

`/llms.txt` at the origin, `/docs/llms.txt` for the guides, `/docs/llms-full.txt` as a concatenation. 404s for `Accept: text/markdown` return a short recovery map instead of the app shell. OpenAPI and `.well-known/api-catalog` stay the machine doors into the JSON API.

Plugin titles in search results now carry the summary. README translations keep the previous completed body until a replacement finishes, so a locale does not flicker empty while a job runs.

## Why the shared sources matter

The visible work is a docs tree, a blog, and an installable plugin. The engineering constraint underneath is more useful: none of those surfaces gets a private copy of catalog facts. The website, CLI, and hub plugin resolve the same install plans. Docs search, Markdown negotiation, `llms.txt`, Atom, and sitemap output are generated from their respective MDX trees.

That removes a common failure mode where the page says one thing and the agent endpoint says another. It also makes authoring stricter. A route or locale file missing from the source tree cannot be patched over with prose embedded in a component; parity and link checks fail instead.

## What to try

Use the surface that matches the job:

- Browse `/docs` when you are learning the publishing contract.
- Fetch `/docs/llms.txt` or a `.md` route when an agent needs the same material.
- Run `npx @dsh-fish/cli` when you want an install plan without opening the site.
- Load `@dsh-fish/hub` when the plan should stay inside a Harness session.

The limitation is deliberate: blog search did not ship in this release, and `/api/search` remains catalog search rather than a second content index.
