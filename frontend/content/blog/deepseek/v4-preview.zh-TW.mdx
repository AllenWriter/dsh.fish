DeepSeek 於 2026 年 4 月 24 日發布 [DeepSeek-V4 預覽版](https://www.deepseek.com/news/v4-preview/)。那篇文章是第一手來源。本文不是轉載，而是截至 Harness v0.1.2-alpha.1，這條公告對目錄所索引的 agent 執行時做了什麼。

## 公告實際寫了什麼

兩個開源權重模型，官方服務上的預設上下文都是 **1M token**：

| 模型 | 總參數 / 啟用參數 | 公告中的定位 |
| --- | --- | --- |
| DeepSeek-V4-Pro | 1.6T / 49B | 程式設計、世界知識、數學——對標閉源 |
| DeepSeek-V4-Flash | 284B / 13B | 更快更便宜；「簡單 Agent 任務上與 Pro 相當」 |

架構主張是 **token 維壓縮加上 DSA**（DeepSeek Sparse Attention）。1M 不是可選的長上下文 SKU，而是標準視窗。

API 的 `base_url` 不變。`model` 改為 `deepseek-v4-pro` 或 `deepseek-v4-flash`。兩個名字都支援思考 / 非思考。公告建議 Agent 場景用思考模式，強度 `max`。

**下線：** `deepseek-chat` 與 `deepseek-reasoner` 於 **2026 年 7 月 24 日 15:59 UTC** 停止。此前分別路由到 V4-Flash 的非思考與思考。過期之後這兩個字串是死名，不是別名。

網頁與 App 以專家模式 / 極速模式暴露這一對。權重與技術報告從公告頁鏈出（Hugging Face / ModelScope、arXiv）。

## Harness 拿它做了什麼

V4 公告在四月。八月人們實際跑的 harness 預覽已經把 V4 當活的家族：

- **v0.1.1-rc.1** 在官方適配器上增加 `DeepSeek-V4-Flash-Vision-Exp`——影像輸入，實驗性，名字就寫著 Exp。
- **v0.1.1-rc.2** 讓適配器優先走 **Files API** 上傳影像並複用已傳檔案，依模型要求縮放和轉格式。
- **v0.1.0-rc.8** 已經為 DeepSeek 適配器打開原生圖片請求（`/goal`、`/plan`、`@` 引用檔案和工作階段）。
- **v0.1.2-alpha.1** 把**已啟用外掛的套件名稱與版本**附在官方 DeepSeek 請求上，並提供可選的 Session 日誌上傳。

所以公告裡「與 Claude Code、OpenClaw、OpenCode 以及 DeepSeek 自研 coding agent 整合」不是貼在未改執行時旁邊的行銷句。隨後幾個月，vision、Files API 和外掛身分都成了這條 API 上的一等公民。

實驗性視覺模型是單獨的 `model` 字串：`deepseek-v4-flash-vision-exp`。API 文件目前寫明 `deepseek-v4-flash` 對應 DeepSeek-V4-Flash-0731，`deepseek-v4-pro` 對應 DeepSeek-V4-Pro-0813——名字不變，快照更新。呼叫方式不變。

## 外掛作者不該忽略的

1. **不要再把 `deepseek-chat` / `deepseek-reasoner` 寫成呼叫方式。** 它們有下線日。四月還對的 README，在 2026 年 7 月 24 日就會錯。
2. **1M 是官方適配器圍繞的視窗。** 假定 128k 裁剪、或把整倉塞進一次 prompt 卻沒有檢索策略的 skill，現在要麼浪費視窗，要麼以另一種方式溢位。
3. **影像是一等的工具結果**，不是邊欄。外掛若產出截圖、圖表或 diff 圖，官方適配器會走 Files API 和 vision-exp。壓縮時要把它們算進去（v0.1.2-alpha.1 已經算了）。
4. **官方適配器能告訴 DeepSeek 載入了哪些外掛。** 套件名丟人、誤導或衝突，現在會跟請求一起走。

## 本目錄不會做什麼

dsh.fish 不替你選模型。安裝計畫從不寫 API key。V4 公告裡的定價和高峰時段屬於 [DeepSeek API 文件](https://api-docs.deepseek.com/quick_start/pricing)，不屬於目錄列。

目錄要做的是讓安裝計畫對準 V4 實際跑在裡面的執行時。外掛 README 還在寫 `export deepseek-chat`，那是可以打進維護分的文件缺陷，不是另一個產品。
