DeepSeek Harness 自身の README は **everything is a plugin** で始まります。市場のスローガンではなく、プロセスの記述です。コアは小さく保ち、能力 — ツール、提供元、承認規則、UI — はすべて profile に列挙されたプラグインとして届きます。下の合成ランタイムは Cordis。論文は [_A Programming Paradigm for Spatiotemporal Composability_](https://arxiv.org/abs/2608.25512) です。

dsh.fish があるのは、その文に運用上の帰結があるからです。すべてがプラグインなら、「これを入れる」は一条のコマンドではなく計画です。どの profile、どのパッケージ、どのファイル、どの設定。このノートは、その二つの事実のつなぎ方です。

## 起動の単位は Profile

`$DSH_HOME`（既定 `~/.dsh`）にユーザーデータが入ります。`profiles/<name>` の下に、一つのセットアップを定義するパッケージと patch があります。起動時は `--profile` で選びます。v0.1.2-alpha.1 では Web UI、Python SDK、ACP はすべて Profile 経由で起動します。別のスタックを載せる裏口はありません。

だから dsh.fish のインストール計画はどれも profile を指名します。プラグインを「harness」に書いて profile を書かないのは、どこにも書かないことです。

## 四つの kind、四つの載面

カタログは型を発明しません。harness がすでに載せるものに名前を付けます。

| Kind | harness がすること |
| --- | --- |
| Bundle | `dsh.bundle` を宣言する npm パッケージ — `dsh plugin add` が profile に入れる |
| Skill | モデルが必要に応じて載せる `SKILL.md` |
| Agent preset | 一つの agent のツール、prompt 節、人格 |
| Profile | 順序付きの bundle の束。実行可能な合成そのもの |

退役した kind（`mcp-server`、`hook-bridge`）は 301 されます。カタログのフィクションだったからです。harness にそれらの名前に合う一等の載スロットはありませんでした。ランタイムが入れられない kind を登録表が残すのは、存在しない製品を売ることです。

## 文書はインストール計画

サイト、CLI（`npx @dsh-fish/cli`）、hub プラグインは同じ計画を印字します。計画は、何かが走る前に読み切れる手順の一覧です。ビルドスクリプトを走らせねばならない git パッケージは別の承認を求めます。そのスクリプトは agent サンドボックスの外で実行されるからです。

計画は、識別子を訳さずに多言語にする理由でもあります。`dsh plugin add`、`SKILL.md`、パッケージ名はどの言語でも英語のままです。囲む枠はそうではありません。

## コアが今も持つもの

「すべてはプラグイン」はコアが空であることではありません。セッションは今も追記専用のイベントログです。ワークスペースは今も agent に渡すディレクトリです。権限は今も名前付きプリセット（既定 `workspace-write`）です。公式 DeepSeek アダプタは今もキーをマシンに留める方法です。

プラグインはそれらの権限の下で動きます。それがハブが守る信頼境界です。profile を変える前に、プラグインが何か、計画が何を書くかを見ます。

## このカタログが拒否するもの

第二の harness ではありません。Cordis を包みません。PTC mode も `@Remote` も再実装しません。Harness が Code Mode を PTC mode に改名したとき、カタログの仕事は旧名を書くのを止めることであり、互換パッドを出すことではありません。

公式ドキュメントでもありません。DeepSeek のガイドは [deepseek-harness.github.io](https://deepseek-harness.github.io/deepseek-harness/) です。dsh.fish のドキュメントはハブへの公開と点数の計算を教えます。二つの木は意図して分かれています。一つはランタイム、一つは登録表。

プラグインの文が結合キーです。将来の Harness が第五の載面を足すなら、ここに kind が増えるか、索引しないかです。プロセスが載せられない型を発明する第三の選択肢はありません。
