DeepSeek Harness’s own README leads with the sentence **everything is a plugin**. That is not a slogan for a marketplace. It is a description of the process: the core stays small, and every capability — tools, providers, approval rules, UI — arrives as a plugin listed in a profile. Cordis is the composition runtime underneath; the paper is [_A Programming Paradigm for Spatiotemporal Composability_](https://arxiv.org/abs/2608.25512).

dsh.fish exists because that sentence has an operational consequence. If everything is a plugin, then “install this” is not one command. It is a plan: which profile, which packages, which files, which settings. This note is how those two facts fit together.

![A profile composes catalog artifacts into one permission-scoped Harness session.](/blog/diagrams/plugin-composition.svg)

## A profile is the unit that boots

`$DSH_HOME` (default `~/.dsh`) holds user data. Under `profiles/<name>` sit the packages and patch files that define one setup. You choose a profile at launch with `--profile`. As of v0.1.2-alpha.1, the Web UI, the Python SDK, and ACP all start through a Profile. There is no side door that loads a different stack.

That is why every dsh.fish install plan names a profile. Writing a plugin into “the harness” without a profile would be writing it into nowhere.

## Four kinds, four load surfaces

The hub does not invent types. It names the things the harness already loads:

| Kind         | What the harness does with it                                                         |
| ------------ | ------------------------------------------------------------------------------------- |
| Bundle       | An npm package declaring `dsh.bundle` — `dsh plugin add` installs it into the profile |
| Skill        | `SKILL.md` the model loads on demand                                                  |
| Agent preset | Tools, prompt sections, and persona for one agent                                     |
| Profile      | An ordered stack of bundles; a whole runnable composition                             |

Retired kinds (`mcp-server`, `hook-bridge`) 301 away because they were catalog fiction: the harness never had a first-class load slot that matched those names. A registry that keeps a kind the runtime cannot install is advertising a product that does not exist.

## An install plan is the document

The website, the CLI (`npx @dsh-fish/cli`), and the hub plugin all print the same plan. A plan is a list of steps you can read before anything runs. A git package that must run a build script asks for a separate approval, because that script executes outside the agent sandbox.

The plan is also why the catalog can be multilingual without translating identifiers. `dsh plugin add`, `SKILL.md`, and package names stay English in every locale. The chrome around them does not.

## What the core still owns

“Everything is a plugin” does not mean the core is empty. Sessions are still append-only event logs. A workspace is still the directory you hand the agent. Permissions are still named presets (`workspace-write` by default). The official DeepSeek adapter is still how keys stay on the machine.

Plugins act with those permissions. That is the trust boundary the hub is for: you inspect what a plugin is, and what the plan will write, before the profile changes.

## What happens when you install a bundle

The useful mental model is not “download a package.” It is **change a composition, then boot that composition**. The hub resolves an artifact into an explicit plan, the client applies those steps to one profile, and the next launch lets Cordis resolve the resulting package graph. Discovery and execution remain separate.

That separation buys you inspectability. You can review the target profile, package source, files, and build-script allowance before a third-party package gets a chance to run. It also creates a hard limitation: dsh.fish can describe what an install will change, but it cannot prove that arbitrary plugin code is safe. A high catalog score is maintenance evidence, not a sandbox certificate.

For a bundle, the shortest useful check is:

```bash
npx @dsh-fish/cli info <artifact-id>
npx @dsh-fish/cli install <artifact-id> --profile <profile-name>
dsh --profile <profile-name> web
```

Read the plan printed by the first two commands. In particular, stop if the source, profile, or requested build allowance is not what you expected.

## What this catalog refuses to be

It is not a second harness. It does not wrap Cordis. It does not re-implement PTC mode or `@Remote`. When Harness renames Code Mode to PTC mode, the catalog’s job is to stop documenting the old name, not to ship a compatibility shim.

It is also not the official docs. DeepSeek’s guide is [deepseek-harness.github.io](https://deepseek-harness.github.io/deepseek-harness/). dsh.fish docs teach you how to publish into the hub and how the score is computed. The two trees stay separate on purpose: one is the runtime, one is the registry.

The plugin sentence is the join key. If a future Harness release adds a fifth load surface, that is a new kind here — or it is not indexed. There is no third option that invents a type the process cannot load.
