README самого DeepSeek Harness начинается с фразы **everything is a plugin**. Это не слоган маркетплейса. Это описание процесса: ядро остаётся маленьким, а каждая возможность — инструменты, провайдеры, правила одобрения, UI — приходит плагином, перечисленным в profile. Среда композиции снизу — Cordis; статья — [_A Programming Paradigm for Spatiotemporal Composability_](https://arxiv.org/abs/2608.25512).

dsh.fish существует, потому что у этой фразы есть операционное следствие. Если всё — плагин, то «поставить это» не одна команда, а план: какой profile, какие пакеты, какие файлы, какие настройки. Эта заметка — как эти два факта стыкуются.

![Profile собирает artifacts каталога в одну ограниченную разрешениями сессию Harness.](/blog/diagrams/plugin-composition.svg)

## Единица запуска — Profile

`$DSH_HOME` (по умолчанию `~/.dsh`) хранит пользовательские данные. Под `profiles/<name>` лежат пакеты и патчи, задающие одну сборку. При старте её выбирают `--profile`. К v0.1.2-alpha.1 Web UI, Python SDK и ACP стартуют через Profile. Боковой двери, которая грузит другой стек, нет.

Поэтому каждый план установки dsh.fish называет profile. Писать плагин «в harness» без profile — писать его в никуда.

## Четыре kind, четыре поверхности загрузки

Каталог не изобретает типы. Он называет то, что harness уже грузит:

| Kind         | Что harness с этим делает                                        |
| ------------ | ---------------------------------------------------------------- |
| Bundle       | npm-пакет с `dsh.bundle` — `dsh plugin add` ставит его в profile |
| Skill        | `SKILL.md`, который модель грузит по необходимости               |
| Agent preset | инструменты, секции prompt и персона одного агента               |
| Profile      | упорядоченный стек bundle; целая исполняемая композиция          |

Снятые kind (`mcp-server`, `hook-bridge`) уходят 301, потому что это была выдумка каталога: у harness никогда не было слота загрузки первого класса под эти имена. Реестр, который держит kind, который рантайм не умеет поставить, продаёт продукт, которого нет.

## Документ — план установки

Сайт, CLI (`npx @dsh-fish/cli`) и плагин hub печатают один и тот же план. План — список шагов, который можно прочитать до того, как что-либо запустится. Git-пакет, которому нужен сборочный скрипт, просит отдельное одобрение, потому что этот скрипт выполняется вне песочницы агента.

План также объясняет, как каталог многоязычен, не переводя идентификаторы. `dsh plugin add`, `SKILL.md` и имена пакетов остаются английскими в каждой локали. Рамка вокруг них — нет.

## Что ядро всё ещё держит

«Всё — плагин» не значит, что ядро пустое. Сессии по-прежнему — журналы событий только на дозапись. Рабочая область по-прежнему — каталог, который вы отдаёте агенту. Права по-прежнему — именованные пресеты (`workspace-write` по умолчанию). Официальный адаптер DeepSeek по-прежнему то, как ключи остаются на машине.

Плагины действуют с этими правами. Это граница доверия, ради которой существует хаб: вы смотрите, что такое плагин и что запишет план, до того как profile изменится.

## Что происходит при установке bundle

Полезная mental model — не «скачать package», а **изменить composition и затем загрузить именно её**. Hub преобразует artifact в явный plan, client применяет его шаги к одному Profile, а при следующем launch Cordis разрешает получившийся package graph. Discovery и execution остаются разделены.

Это разделение даёт проверяемость. До запуска стороннего package можно просмотреть целевой Profile, источник package, файлы и разрешение на build script. Но оно же показывает жёсткое ограничение: dsh.fish может описать изменения install, однако не может доказать безопасность произвольного plugin code. Высокий catalog score — свидетельство maintenance, а не сертификат sandbox.

Короткая проверка bundle выглядит так:

```bash
npx @dsh-fish/cli info <artifact-id>
npx @dsh-fish/cli install <artifact-id> --profile <profile-name>
dsh --profile <profile-name> web
```

Прочитайте plan, который выводят первые две команды. Остановитесь, если источник, Profile или запрошенное разрешение на build не совпадает с ожиданиями.

## Чем этот каталог отказывается быть

Это не второй harness. Он не оборачивает Cordis. Он не переписывает PTC mode или `@Remote`. Когда Harness переименовывает Code Mode в PTC mode, работа каталога — перестать документировать старое имя, а не выпускать прокладку совместимости.

Это и не официальные документы. Гайд DeepSeek — [deepseek-harness.github.io](https://deepseek-harness.github.io/deepseek-harness/). Документы dsh.fish учат публиковать в хаб и как считается балл. Два дерева нарочно разделены: одно — рантайм, другое — реестр.

Фраза про плагин — ключ соединения. Если будущий релиз Harness добавит пятую поверхность загрузки, здесь появится новый kind — или запись не индексируется. Третьего варианта, который изобретает тип, который процесс не умеет грузить, нет.
