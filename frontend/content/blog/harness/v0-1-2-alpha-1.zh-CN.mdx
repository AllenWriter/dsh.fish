[v0.1.2-alpha.1](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.2-alpha.1) 是 2026 年 8 月 27 日发布的预览版。changelog 很长，因为好几条线同时动了：会话怎么启动、插件如何向 DeepSeek 表明身份、子代理怎么拉起、以及 headless 进程允许往哪里打日志。下面按这些行对照它们点名的代码来读，而不是复述一遍列表。

标签是 `dsh-v0.1.2-alpha.1`。`npx @deepseek-ai/dsh web` 仍然会解析到当前预览包；排查回归时请钉死这个 tag。

## 插件会出现在请求里

官方 DeepSeek 适配器会把**每个已启用插件的包名和版本**附在出站请求上。部署侧可以关掉。同一条链路上还有一个**默认关闭、需显式打开**的 Session 日志增量上传。

这对目录同样成立。dsh.fish 上的一行是写入某个 named profile 的安装计划。这个版本之后，模型提供方能看见这些包里哪些真正加载了。你发布的 bundle 名字，就是官方适配器在用时离开本机的那个名字。

插件还可以**在模型设置页注册提供方登录控件**。这不是通用设置卡片，而是专门把 OAuth 或 token 登录放在内置提供方旁边。

## 启动就是 Profile，包括 Python 和 ACP

即使用 Python SDK 或 ACP 进入，应用也通过 `dsh` Profile 启动。Python SDK runtime 增加了 **Windows x64** 发行包。

ACP（Agent Client Protocol）不再是半截实现。会话控制、模型设置、MCP、权限和取消都列为已补齐。如果之前卡在缺某个控制，用这个版本重新测——仍然是 preview，仍然没有稳定性承诺。

## 子代理可以选自己的模型

两件相关的事：

- 在父任务已有的授权范围内，Agent 可以为子代理选择提供方、模型和推理力度。
- 启动子代理时可以指定提供方、模型、推理力度和**最大输出长度**。
- Claude Code 与 Codex 子代理使用**配置的模型**，不再默认继承父会话。

第一项是策略：子代理不是父模型槽的克隆。后两项是你在 profile 里钉死它的方式。把 Claude Code 或 Codex 当 bundle 装进 hub profile 的，现在还应该写明这些子进程跑哪个模型。

## 从树里拿掉的东西

**ApiProxy 已移除。** changelog 写明迁移到 `@Remote` 网关已完成。仍在 import 旧调用路径的代码不会加载。

**Code Mode 现名为 PTC mode。** 已有会话记录仍可读。截图里还写着 “Code mode” 的英文预设已经过时；运行时名字是 PTC。

**公网 WebFetch 默认开启**，带 SSRF 防护，公网请求不再逐次审批。这和以前的「每次都问」相反。如果某个 profile 把那次审批当成闸门，对公网 URL 它已经不在了。

**经网络访问 Web UI 时，启动链接必须带一次性 token。** 本机 loopback 上的 `dsh web` 不变；绑到网上的监听现在用链接本身鉴权。

Headless 运行把进度打到 **stderr**。**stdout 只输出最终结果。** 从 stdout 里 grep 工具轨迹的脚本，在这一轮结束前会什么都看不到。

## 会话 UI 和存储

会话流会在每条已完成回答前折叠过程内容和 System prompt，回答后可展开精确 token 用量，正文宽度可拖。这些是 UI。对大历史更要紧的是存储：会话记录更省磁盘；截断的日志尾会自动修复，并警告受影响的会话。

macOS/Linux 上持久 PowerShell 不再过早启动。Linux 上持久 Bash 不再在管道中途返回空输出。Bash 拉起大量子进程时 macOS 宿主不再卡死。Profile 配置的 Agent Preset 目录启动时不再丢失；无法加载的 preset 会在切换前被标出来。

## 安全说明

本 tag 更新了 Safety Notice：DeepSeek Harness **尚未接受安全审计**。沙箱、审批与权限控制**不能保证隔离**。这是官方文本，不是论坛传言。继续把 `danger-full-access` 当成它一直是的那样。不要把新的 WebFetch 默认理解成沙箱变严了。它没有。

## 本目录会怎么对待它

dsh.fish 的安装计划仍然只写 `$DSH_HOME` 下的 named profile。它们不会打开 Session 日志上传，也不会发明 ApiProxy 回退。文档还在写 ApiProxy 的插件，应视为面向比这个 tag 更旧的树。

评分模型没变。变的是分数所描述的运行时：README 仍写 Code Mode、仍贴 ApiProxy 片段，相对 v0.1.2-alpha.1 是文档缺陷，不是另一个产品。
